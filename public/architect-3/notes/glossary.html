Glossary & Ubiquitous Language

TL;DR

Most expensive misunderstandings are about words, not technology. Keep a glossary of the words that matter: each with its meaning in each context (a word can mean different things in different bounded contexts, and that's fine if it's written down), what not to confuse it with, and its name in the code. Use the same words in code, docs, contracts and reports: Domain-Driven Design calls it a ubiquitous language.

1The situation Larder, 9 February 2027

January's first monthly report for Korenwolf's three offices says 96.1 % complete deliveries, below the 98 % in the contract. Ruben calls Mo, unhappy. The cause: the report counted each crate as a delivery. The contract defines a delivery as everything for one office on one morning. By that measure, January was 98.6 %. One word, two meanings, and a client's trust dented over arithmetic.

  • The same word means different things to Dispatch, Fulfilment, sales and the contract.
  • Reports and code pick a meaning silently.
  • Every new hire and every new client learns the words by accident.

2Real-life analogy the rulebook's definitions page

A football rulebook defines “goal” (the whole ball over the whole line), “offside” and “handball”. Players, referees and commentators still argue, but about the game, not about what the words mean. A league where every referee had their own definition of a goal wouldn't last a season.

3How it solves it each word, per context, in the code too

Ana and Mo wrote the glossary in an afternoon, starting from the words in the Korenwolf contract and the bounded contexts from Vol. 1. Each row says what the word means in each context, what not to confuse it with, and its name in the code, so the report now uses OfficeDelivery, not a count of crates. Mo sent Ruben the corrected report (98.6 %) with the definition attached. The glossary became arc42 section 12, and the contract template links to it.

  1. Start from a misunderstanding

    The word that just caused trouble, then the contract's and the domain's key words.

  2. One row per word

    Meaning, in each bounded context; what not to confuse it with.

  3. Add the code name

    The class, table or event name, so code and words match.

  4. Use it everywhere

    Reports, contracts, docs, tickets; rename code where it disagrees.

  5. Add words as they appear

    New client, new country, new feature: new rows.

  6. Review with outsiders

    Sales, legal, a client: do they read the words the same way?

Vocabulary for the exam

Ubiquitous language
The shared words used by business and code alike.
Bounded context
An area where a word has one meaning.
Glossary
The list of words that matter and what they mean.
Homonym
One word with several meanings (delivery).
Synonym
Several words for one thing (drop, stop, delivery).
Context map
How bounded contexts relate and translate words.

4Gains vs losses nothing is free

What we gain

  • Fewer expensive misunderstandings with clients and teams.
  • Code and business speak alike.
  • Faster onboarding for new hires and new clients.
  • Reports that match contracts.
  • Bounded contexts made visible in plain words.

What we lose

  • Upkeep: new words, new contexts.
  • Renaming code to match costs effort.
  • Can turn pedantic if every word gets a row.
  • Doesn't help if nobody links to it.

6Common pitfalls the usual ways this goes wrong

  • One meaning forced everywhere

    “Order” must mean the same in every context. Fix → write the meaning per context; that's what bounded contexts are.

  • A glossary nobody links

    A page in a corner. Fix → link it from contracts, reports and onboarding.

  • Code disagrees

    The docs say OfficeDelivery; the code says Delivery. Fix → rename the code, or note the mapping.

  • Every word

    A dictionary of 400 terms. Fix → only words that matter or have caused trouble.

7When to use it (and when not)

Use it when…

  • Client contracts with measured service levels.
  • Systems with several bounded contexts.
  • Onboarding new hires and new clients.
  • After any misunderstanding about a word.

Skip it when…

  • Tiny teams in one domain where words never collide.
  • Generic technical terms: link to an external glossary.

8Self-check quiz

Why did January's report show 96.1 %?

It counted crates as deliveries; the contract defines a delivery per office per morning.

Can a word mean different things?

Yes, in different bounded contexts, as long as each meaning is written down.

What columns does a good glossary have?

Word, context, meaning, not to confuse with, name in code.

What's a ubiquitous language?

Shared words used the same way by the business and in the code.

try it

List the ten words your team and your customers use most. For each, ask three people (an engineer, a product person, a salesperson) what it means. Write the glossary rows where they disagree, and link it from your contracts or reports.

remember!!

Define the goal before the match. One word, per context, in the code too.
