How Do We Strangle a Customer System?

TL;DR

Strangling a customer system means two systems run side by side for years. Make it safe with five things: one system of record per account, a router that knows which system answers, a back-feed for old processes that still need data, a way back for each wave, and a nightly reconciliation of counts and balances. Move customers in groups that make sense to the business, not to the database.

  • Family: the data and its seams
  • Lives in: Schedule 2 v1.1, §4 (migration architecture)
  • Pairs with: mainframe integration, migration in waves

1The situation The Grid, 30 November 2027

The bid promised to replace MAVIS in waves, district by district. Discovery now has enough facts to design how two customer systems live side by side, possibly until 2030.

  • Customer Ops' call-centre tools must know, for any customer, which system to ask.
  • Seven MAVIS processes (collections letters, regulatory returns, the meter feed, and four more) still need migrated customers' data.
  • Hollis's question at the design authority: “And if wave 1 goes wrong on the Sunday, how do we go back?”

2Both sides of the table the same moment, seen twice

MetroVolt Hollis and Customer Ops

For MetroVolt, two systems at once means two places to look, two chances of disagreement and a call-centre agent asking “which screen?”. Hollis wants it impossible for an account to live in both. Customer Ops wants nothing to change on their screens.

“One customer, one truth, and a way back.”

Wrenfield Ines and Hana

Wrenfield must design the in-between years so they're boring: clear ownership, a router, old processes still fed, and every wave reversible. A strangler that can't be reversed is just a slow big bang.

“Make the coexistence dull, measurable and undoable.”

The strangler fig is easy to draw and hard to run. The hard part isn't the new system; it's the years in between.

3Real-life analogy moving a library across town

A library moving to a new building moves one section at a time. The catalogue says which building each book is in. The old building still answers questions about moved books for a while, so readers aren't lost. Each move can be reversed if the new shelves fail. And every night, someone counts the books in both buildings to make sure none fell off the van.

4How it works one owner, a router, a back-feed, a way back, a reconciliation

One system of record per account. Each account has a flag: MAVIS or Lodestar. Never both. When a wave moves, the flag flips for those accounts and MAVIS makes them read-only.

A router. Customer Ops' tools ask one service, “who answers for account 4417…?”, and are sent to MAVIS or Lodestar. Agents see the same screens; the router hides the seam.

A back-feed. The seven MAVIS processes that still need migrated customers get a nightly feed from Lodestar in MAVIS's own format, including COPYMTR's meter file. Each process gets an owner and a retirement date (most retire with wave 4).

A way back. For 14 days after each wave, MAVIS keeps the migrated accounts up to date through the back-feed, so flags can be flipped back if the wave fails. After 14 days, the decision is final.

Nightly reconciliation. Every night: account counts, balances and open debts compared between the two systems, per district. Any difference stops the next wave.

  1. Choose business-shaped groups

    Districts customers and staff understand.

  2. One owner per record

    A flag, never two masters.

  3. A router in front

    Users don't need to know which system answers.

  4. Feed the old processes

    A back-feed with owners and retirement dates.

  5. Keep a way back

    A rollback window per group.

  6. Reconcile nightly

    Differences stop the next move.

Vocabulary

Strangler fig
Replacing an old system gradually while both run.
System of record
The system whose data is authoritative for a record.
Router (façade)
A layer that sends each request to the right system.
Back-feed
Sending data from the new system back to the old one's processes.
Rollback window
How long a migration can still be reversed.
Reconciliation
Comparing totals between systems to prove nothing was lost.

5What the contract says how the design schedule grows

for DA

§4.1 Each customer account has exactly one system of record at any time.

Hollis's sentence. it's now a requirement we can test.

3.3 (SOW) Elements of Schedule 2 identified as subject to discovery may be refined by agreement following the discovery phase without a Change Request, provided the Charges are unaffected.

the router is a refinement. the back-feed for 7 processes isn't free: it's in the change request.

In plain words: refining the design within discovery is allowed without a change request only if the price doesn't move. Be honest about which parts are refinements and which are new work.

9Common pitfalls the usual ways this goes wrong

  • Two masters for one record

    Updates collide. Fix → one system of record per account.

  • Users choosing the system

    Agents look in the wrong place. Fix → a router hides the seam.

  • Forgetting old processes

    Letters stop, reports break. Fix → a back-feed with owners.

  • No way back

    A strangler becomes a slow big bang. Fix → a rollback window per wave.

  • No reconciliation

    Missing customers found months later. Fix → nightly counts and balances.

10When to use it (and when not)

Use it when…

  • Replacing a system of record gradually.
  • Coexistence will last months or years.
  • Groups of records can move separately.

Skip it when…

  • The old system is small enough to switch over in one tested weekend.

11Self-check quiz

What does “one system of record per account” prevent?

Two systems updating the same account and disagreeing.

What does the router do?

Sends each request to whichever system owns the account, so users don't have to know.

What is the back-feed for?

Seven MAVIS processes that still need migrated customers' data.

How long can a wave be rolled back?

Fourteen days.

What stops the next wave?

Any difference in the nightly reconciliation of counts and balances.

what would you do?A Customer Ops manager asks for agents to see both MAVIS and Lodestar data side by side “just in case”. What do you say?

Offer read-only history from MAVIS through the router for migrated customers, but keep one system of record: two editable views of the same customer is how updates get lost.

try it

Pick something you'd replace gradually. Write the five parts: the groups you'd move, the ownership flag, the router, what the old system still needs fed, and how you'd go back.

remember!!

A strangler is safe only with one owner per record, a router, a back-feed, a way back, and a nightly count.
