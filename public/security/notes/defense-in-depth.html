Defence in Depth

TL;DR

Every control fails sometimes: a bug, a misconfiguration, a phished password. So stack independent layers (edge protection, strong identity, input handling, least privilege, encryption, monitoring), each catching different failures, so no single mistake means a breach. Choose layers that fail for different reasons, and make sure you'd notice when one is crossed.

  • Family: security architecture
  • Origin: military strategy; NSA guidance (2000s)
  • Related idea: the Swiss cheese model
  • Pairs with: zero trust, threat modelling, audit logging

1The problem why do we even need this?

Many systems rely on one strong wall: a firewall, a login page, or “it's internal”. When that one control has a bug, there's nothing behind it, and often nobody notices.

  • A single auth bug exposes every record.
  • The database user is admin, data isn't encrypted, and nothing alerts.
  • “The WAF will catch it” replaces safe code.

2Real-life analogy the castle

A castle doesn't rely on one wall. There's a moat, an outer wall, an inner wall, guards at the keep, and the treasure in a locked chest. Lookouts raise the alarm at each step, so defenders have time to respond.

  • Each obstacle is a layer.
  • Different obstacles stop different attacks: diversity.
  • Lookouts are monitoring: a layer crossed is a signal.

3How it solves it layers that fail differently

Think of slices of Swiss cheese: each has holes, but the holes rarely line up. A breach needs every layer to fail at once.

  1. Start from the threat model

    List the main threats and which layers stop each one.

  2. Cover prevent, detect, respond

    Not only walls: logging, alerts and a practised incident plan.

  3. Make layers independent

    Different mechanisms and owners, so one mistake doesn't disable several.

  4. Assume each layer can fail

    Ask: if this layer is bypassed, what's the next one?

  5. Don't let layers excuse each other

    “The WAF will catch it” is not a reason for unsafe code.

  6. Test the layers

    Pen tests, chaos-style game days, alert drills.

Vocabulary for the exam

Layer / control
One mechanism that reduces risk.
Swiss cheese model
Breaches happen when holes in all layers line up.
Preventive control
Stops an attack (MFA, validation).
Detective control
Notices an attack (logs, alerts).
Corrective control
Limits damage and recovers (backups, revocation).
Single point of failure
One control whose failure exposes everything.

Feature: customer data export

edge        rate limit 5 exports/hour/tenant · WAF managed rules
identity    SSO + passkey · re-authenticate before export (step-up)
app         schema-validated params · parameterized queries · tenant RLS
privilege   export worker role: SELECT on customers only · no DELETE
data        export file encrypted (KMS, per-tenant key) · signed URL, 10 min
detect      audit: customers.export (ok/denied) · alert on >3 exports/day
respond     runbook: revoke sessions, rotate keys, notify tenant admin

4Gains vs losses nothing is free

What we gain

  • No single point of failure.
  • Time to detect and respond before real damage.
  • Resilient to bugs and misconfigurations.
  • Smaller breaches when one happens.

What we lose

  • More cost and complexity.
  • Possible friction if layers stack up for users.
  • False confidence if layers aren't independent.
  • More things to monitor and maintain.

6Common pitfalls the usual ways this goes wrong

  • Layers that share a weakness

    Three checks all trusting the same header. Fix → use different mechanisms and data sources.

  • Only preventive layers

    Walls but no lookouts: breaches go unnoticed for months. Fix → invest in detection and response too.

  • Layers as excuses

    “The WAF blocks SQL injection, so we skip parameters.” Fix → every layer must stand on its own.

  • Stacking friction on users

    Five prompts to change a setting; users find workarounds. Fix → put friction where risk is highest (step-up).

Use it when…

  • Systems exposed to the internet.

8Self-check quiz

What's the core idea of defence in depth?

Multiple independent layers, so no single failure leads to a breach.

Why must layers be independent?

If they share a weakness, one failure disables several layers at once.

Name the three kinds of controls.

Preventive, detective and corrective (respond/recover).

Is a WAF a reason to skip parameterized queries?

No. Each layer must stand on its own; the WAF is an extra layer, not a replacement.
