Testing Patterns

Structure, test doubles, smarter techniques and reliability: the patterns behind a test suite that is fast, honest and calm to keep green.

Structure shape the suite and every test in it

  1. 01Test PyramidMany fast unit tests, fewer integration tests, a handful of end-to-end tests.p. 01
  2. 02Arrange–Act–AssertEvery test in three clear blocks: set up, do one thing, check the result.p. 02
  3. 03Test Data BuildersBuild valid test objects with sensible defaults; spell out only what matters.p. 03
  4. 04Page ObjectsHide selectors behind a class per page, so UI tests read like user stories.p. 04

Doubles & boundaries deal with databases, networks and other teams

  1. 05Test Doubles (Stubs, Spies, Mocks)Stand-ins for slow or unpredictable dependencies, each with its own job.p. 05
  2. 06FakesA small working version of a dependency, like an in-memory repository.p. 06
  3. 07Throwaway ContainersTest against the real database or broker, started fresh in a container.p. 07
  4. 08Contract TestingCheck that a service and its clients still agree on the API, without a full deploy.p. 08

Smarter techniques find the bugs example tests miss

  1. 09Property-Based TestingState a rule that must always hold and let the tool hunt for counter-examples.p. 09
  2. 10Snapshot (Approval) TestingSave the approved output once; fail when it changes, and review the diff.p. 10
  3. 11Mutation TestingPlant small bugs in the code and check that the tests notice.p. 11
  4. 12Characterization TestsPin down what legacy code does today before you dare to change it.p. 12

Reliability & speed keep the suite fast, green and trusted

  1. 13Controlled Time & RandomnessInject the clock, the random seed and the ids, so every run is the same.p. 13
  2. 14Flaky Test QuarantineDetect tests that pass and fail at random, isolate them and fix the cause.p. 14
  3. 15Parallel & Selective RunsSplit the suite across workers and run only the tests a change can affect.p. 15
