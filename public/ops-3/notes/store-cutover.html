Cutting Over a Store

TL;DR

A migration plan says what moves; a cutover plan says how the night goes. It covers a shadow run that proves the new system first, go / no-go criteria decided at a set time by a named person, the switch in the quietest hour with steps and times, people on site for the first real work, and a way back kept open for a fixed period. Reuse the same plan for each site, and make it shorter each time.

1The situation Larder, March–April 2027

Ana's plan moves each store from StockPilot to WMS B through a router per store: Zuid on 19 April, then Noord, Rotterdam and Utrecht, with StockPilot off by September. The architecture is clear. The night itself isn't written down: who does what at 23:00 on a Sunday, how Tomás knows it worked at 06:00 on Monday, and what makes someone say “go back”.

  • A migration that's clear on a diagram can still go wrong at 23:40.
  • “Go” decided by mood, late at night, is a bad decision.
  • The store opens at 07:00 whatever happens.

2Real-life analogy the railway's signalling weekend

When a railway switches a line to new signalling, the new system runs alongside the old for weeks, silently, comparing. The switch night has a timetable to the minute, a named person decides go or no-go at a set time, the first train carries engineers, and the old system is kept ready to switch back until Wednesday.

3How it solves it shadow, go / no-go, switch, first shift, way back

Eli writes one cutover plan, used first for Zuid:

  • T−7: shadow week. WMS B gets every stock change, and the difference from StockPilot is checked daily. Zuid's is 0.3 %, under the 0.5 % limit.
  • Sunday 18 April, 21:00: go / no-go, decided by Eli with Tomás against four written criteria: difference ≤ 0.5 %, the test pick list prints, on-call plus Eli and the store lead are available, and no SEV1 or SEV2 is open.
  • 23:15, after the store closes: Zuid's router switches to WMS B. A test pick list prints at 23:40.
  • Monday 06:00: Tomás and Eli are in the store for the first real picks.
  • Way back until 2 May: switch the router back. StockPilot stays read-only.

The dates sit on the change calendar, clear of King's Day (26–28 April). Noord, on Monday 24 May, uses the same plan. Its one surprise is the pick-list label format, fixed by 06:40, and that becomes a criterion: “a real label prints”. Rotterdam (21 June) and Utrecht (26 July) follow, each plan a page shorter.

  1. Prove the new system in a shadow run

    Compare daily; set a limit.

  2. Write go / no-go criteria in advance

    Checked at a set time by a named person.

  3. Switch in the quietest hour

    Steps and times, written down.

  4. Be there for the first real work

    On site, at opening time.

  5. Keep a way back for a fixed period

    And say when it closes.

  6. Reuse and shorten the plan

    Each site adds a criterion and removes a step.

Vocabulary for the exam

Cutover
The moment work moves from the old system to the new.
Shadow run
The new system runs alongside the old, without being used, to compare.
Go / no-go
A decision at a set time, against written criteria.
Way back
How to return to the old system, and until when.
Hypercare
A period of close watching just after a cutover or launch.
Read-only
The old system can be looked at but no longer changed.

6Common pitfalls the usual ways this goes wrong

  • No shadow run

    The first real comparison is Monday's picks. Fix → compare for a week first.

  • Go / no-go by mood

    Tired people say go at midnight. Fix → written criteria, a set time, a name.

  • Nobody on site

    The store finds problems alone at 06:00. Fix → be there for the first shift.

  • A way back with no end

    Two systems run forever. Fix → say when the way back closes.

7When to use it (and when not)

Use it when…

  • Moving a site, team or customer group to a new system.
  • Any switch where the old and new can run side by side.
  • When the business can't stop for the switch.
  • Repeated migrations, store by store.

Skip it when…

  • Changes behind a flag that can be turned off in seconds.

8Self-check quiz

What does a cutover plan add to a migration plan?

How the night goes: shadow run, go / no-go, the switch with times, people on site, a way back.

What were Zuid's go / no-go criteria?

Difference ≤ 0.5 %, a test pick list prints, the right people available, no SEV1 or SEV2 open (and after Noord: a real label prints).

Why switch at 23:15 on a Sunday?

It's the quietest hour, after closing, with the whole night before the 07:00 opening.

What was Zuid's way back, and until when?

Switch the router back to StockPilot (≈ 5 minutes), until Sunday 2 May 23:00.

What did Noord add to the plan?

A criterion: a real label prints (the label format surprise).

what would you do?At 21:00 on cutover night the shadow difference is 0.7 %. Everyone is ready and keen. What happens?

No-go: the criterion is ≤ 0.5 %. Find the cause, fix it, and pick a new night from the calendar. Going on enthusiasm is exactly what the criteria exist to stop.

try it

For your next migration or big switch, write the night's plan on one page: shadow, go / no-go criteria and time, the switch steps, who's there for the first real work, and when the way back closes.

remember!!

Plan the night, not just the architecture: shadow first, go / no-go by criteria at a set time, people on site, a way back with an end date.
