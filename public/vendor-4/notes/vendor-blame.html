Whose Fault Is the Billing Failure?

TL;DR

When another vendor blames you, don't answer the email; go to the evidence together. Use the interface agreement's joint triage: the same samples, the same logs, both teams at one table, within hours. Find the cause before the culprit, fix it, improve the agreement so it can't happen again, and write a summary with no names in it. You'll need this vendor again tomorrow.

1The situation The Grid, 16 May 2028

Integration testing with Halvorsen starts on Tuesday 16 May. Halvorsen's test system rejects 3.1 % of the records in Wrenfield's first full file.

  • At 11:20, a Halvorsen engineer emails Hana: “Wrenfield's extract is malformed. Please fix.” Copied to Elaine and Sven.
  • Hana's reply, half-written, begins: “Our file follows v1.2 exactly, unlike…”
  • The pilot is 20 days away. Billing cycles on Halvorsen are one of its acceptance criteria.

2Both sides of the table the same moment, seen twice

MetroVolt Elaine

Elaine sees two suppliers arguing by email, copied to her, three weeks before the pilot. She doesn't care whose fault it is. She cares whether customers will get bills in June, and whether her suppliers can sort it out without her.

“I'm copied. That means it's about to be my problem.”

Wrenfield Hana and Ines

Hana is sure the file is right. She may well be. But proving it by email will start exactly the war IA-01 was written to prevent, and make Wrenfield look as defensive as Halvorsen. Ines needs the cause, fast, and a relationship that survives finding it.

“Don't win the email. Find the cause.”

In a blame war, both vendors usually have part of the cause. In this one, neither vendor did anything wrong on purpose.

3Real-life analogy two mechanics and a car that won't start

The garage that fitted the new battery says the old alternator is faulty. The alternator specialist says the battery's wrong. The car owner doesn't need their letters. A good pair of mechanics open the bonnet together, put a meter on it, and find the loose connector neither of them fitted. Then they tell the owner what it was, not whose it was.

4How it works the same evidence, at one table, within four hours

Ines asks Hana not to send her reply. Instead, under IA-01 (signed in August 2027), she calls a joint triage: “a rejected file is MetroVolt IT on-call's to start, joint, by evidence, within four hours”. MetroVolt IT's lead chairs it at 14:00. Sven joins by phone.

The evidence: a sample of 200 rejected records, the file header, and Halvorsen's parser logs. The header says SPEC=1.2. The logs show the test system running parser version 1.1, which doesn't know address line 4. Halvorsen updated production in December; the test system was never updated. Every rejected record has an address line 4.

Nobody's careless; a test environment was forgotten. Halvorsen updates its test system in nine days. IA-01 v1.2 adds a rule: every environment, test included, must reject a file whose spec version it doesn't support, loudly. The triage summary goes to Elaine at 17:00: cause, fix, date, the agreement change. No names. Sven calls Ines that evening to say thank you for the tone.

  1. Don't answer the blame email

    Not even to correct it.

  2. Call the triage the agreement defines

    Within hours, with the right chair.

  3. Same evidence on one table

    Samples, headers, logs, versions.

  4. Find the cause before the culprit

    Usually a gap, not a person.

  5. Fix it and improve the agreement

    So it can't recur.

  6. Summarise without names

    Cause, fix, date, change.

Vocabulary

Joint triage
Investigating a cross-supplier problem together, by evidence.
Blameless summary
A write-up of cause and fix that doesn't name individuals.
Environment drift
Test and production systems running different versions.
Interface agreement
The written rules for a connection between systems and suppliers.
Root cause
The underlying reason, not the first visible symptom.
Defect ownership
Who fixes a defect, decided after the cause is known.

5What the contract says the agreement that did the work

Interface agreement IA-01 · v1.226 May 2028
evidence first

IA-01, 4 Defects at the interface are assigned to a party only after joint triage on the evidence listed in section 3.

Sven's sentence from 2027. it saved us from our own reply.

IA-01, 5 Every environment, including test environments, shall reject a file whose stated specification version it does not support.

the lesson, written into the agreement.

In plain words: a good interface agreement turns blame emails into a triage with rules. Use it the first time, even when you're sure you're right, and improve it with whatever the triage teaches.

9Common pitfalls the usual ways this goes wrong

  • Winning the email

    You start a war. Fix → don't reply; triage.

  • Arguing without evidence

    Opinions against opinions. Fix → samples, headers, logs.

  • Naming people

    The other vendor's engineer is humiliated. Fix → cause, not culprit.

  • Fixing but not preventing

    It happens again in wave 2. Fix → improve the agreement.

  • Leaving the client out

    They hear about it anyway. Fix → a summary the same day.

10When to use it (and when not)

Use it when…

  • Another vendor blames you.
  • A defect crosses a supplier boundary.
  • The client is copied on an accusation.

Skip it when…

  • The defect is clearly inside your own system: just fix it and say so.
