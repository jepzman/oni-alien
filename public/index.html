?How every note is laid out

  1. The problem: what breaks without the pattern, with a doodle.
  2. Real-life analogy: an everyday version, plus a “translate to software” table.
  3. How it solves it: diagrams, steps, vocabulary and a code card.
  4. Gains vs losses: the trade-off T-chart.
  5. Architecture ratings: nine characteristics, before → after.
  6. Common pitfalls: each with its fix.
  7. When to use it: and when to skip it.
  8. Self-check quiz: tap a question to see the answer.

★The nine ratings

Every note scores the pattern from 1 (poor) to 5 (great) on the same nine things, comparing a system without the pattern to the same system with it.

Simplicity
Fewer moving parts, fewer surprises.
Low cost
Infrastructure, tooling and people. High = cheap.
Deployability
Small, independent, safe releases.
Testability
Isolated parts with clear contracts.
Scalability
Handles more users and data by adding machines.
Elasticity
Scales up and back down quickly for spikes.
Fault tolerance
One failure stays contained.
Performance
How fast a typical request is.
Evolvability
How easily the system can change shape.

first law

Everything in architecture is a trade-off. If you think you've found one that isn't, you haven't found the cost yet.
