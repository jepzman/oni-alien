✎A note from the author why I made these journals

Your AI agent can write a saga orchestrator in eleven seconds. It cannot tell you whether you needed one.

These notebooks are for that second part. They're for new developers learning what all the arrows mean, and for experienced ones who've been nodding along in design reviews since 2019. They're short on purpose. Read one on the train, in a tunnel with no signal, or while the progress bar says “Thinking…” for the fourth minute.

Each note gives you three things:

  • Better questions for the code review. When the agent says “Done! ✅”, you'll know to ask: is this idempotent? Where's the timeout? What happens when it runs twice? Ask before you tell your boss it's done. Not after.
  • Better prompts for the next ticket. “Add retries” gets you a loop. “Add capped retries with jitter and an idempotency key, only on 5xx” gets you a pattern. Vocabulary is leverage.
  • A sense of the trade-offs. Every pattern here has a “what we lose” column. The agent rarely volunteers that column. Somebody in the room should know it exists.

The honest origin story: I had usage left before my weekly limit reset, and wasting it felt worse than wasting snacks. So I asked the agent to help me write notes about what agents get wrong. It found this very relatable.

Read one note a day. Argue with the ratings. Doodle in the margins.
by Jefrey Romel Tagunicar

?What's inside every note same eight sections

  1. The problem the pattern solves, with a doodle.
  2. A real-life analogy and a “translate to code” table.
  3. How it works: diagrams, steps, vocabulary, a code card.
  4. Gains vs losses, side by side.
  5. Nine ratings picked for each journal's subject.
  6. Common pitfalls and their fixes.
  7. When to use it, and when not to.
  8. A self-check quiz.
