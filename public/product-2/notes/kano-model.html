Kano Model

TL;DR

Not all features please customers the same way. Must-be features only prevent anger: nobody thanks you for them. Performance features please in proportion: more is better. Attractive features delight because nobody expects them. Some are indifferent: nobody cares. Find out which is which by asking customers two questions per feature (how would you feel if it were there? and if it weren't?), not by guessing. Then fix the must-bes first, compete on performance, and add a few attractors.

  • Lives in: a short in-app survey and a table

1The situation Larder, 16 February 2026

With the flag shipping next week, the discussion turns to what comes after. Femke is sure recipe ideas will delight customers. Sam calls the “no swaps” flag “just basic, they'll expect it”. Dee thinks live order updates are a nice extra. Everyone is confident; nobody has asked customers. Grace realises they're arguing about three different kinds of value without a word for any of them.

  • People guess what delights customers from their own taste.
  • Basic needs get treated as features to celebrate, or ignored until customers leave.
  • “Delighters” get built while basics are still broken.

2Real-life analogy the hotel room

Grace learned this in hotels. Clean sheets are a must-be: nobody writes a review praising them, everyone writes one when they're dirty. Wi-fi speed is performance: the faster, the happier. A handwritten welcome note is attractive: unexpected, remembered. And the trouser press? Indifferent: it costs money and nobody cares. Each needs a different decision.

3How it solves it two questions per feature, then the curves

For each feature, the survey asks: if Larder had this, how would you feel? and if it didn't, how would you feel? (like it, expect it, don't mind, can live with it, dislike it). The pair of answers puts each response in a category. With 212 answers in a week, the debate settled: the flag is basic (fix it, don't celebrate it), approvals are performance (worth investing in), and recipe ideas leave most customers cold.

  1. Pick 4–8 features

    Ones people disagree about; describe each in one customer-facing sentence.

  2. Ask the two questions

    Functional (if it's there) and dysfunctional (if it's not), five answers each.

  3. Reach the right customers

    An in-app survey or email to a sample; 100+ answers per segment if you can.

  4. Classify each answer

    Use the Kano table: e.g. “expect it” + “dislike it” = must-be.

  5. Take the most common category

    Note the split; a close call means the segment matters.

  6. Decide by category

    Fix must-bes quietly, invest in performance, add a few attractors, drop the indifferent.

Vocabulary for the exam

Must-be
Expected; missing it angers, having it pleases nobody.
Performance
More is better, in proportion.
Attractive
Unexpected; delights even in a small form.
Indifferent
Customers don't care either way.
Reverse
Some customers actively don't want it.
Decay
Attractors become performance, then must-be, over time.

# Kano survey · in-app, express and slot customers · 212 answers

Q1  If you could approve or refuse each substitute in the app within
    2 minutes, how would you feel?        (like / expect / neutral / tolerate / dislike)
Q2  If you couldn't, how would you feel?  (same five answers)
    ... same pair for each feature

| Feature                         | Must-be | Perform. | Attract. | Indiff. | Result         |
|---------------------------------|---------|----------|----------|---------|----------------|
| Approve substitutes in the app  | 22 %    | 48 %     | 18 %     | 12 %    | performance    |
| "Never swap this" flag per item | 41 %    | 24 %     | 9 %      | 26 %    | must-be        |
| Live order update with photo    | 8 %     | 21 %     | 39 %     | 32 %    | attractive     |
| Recipe ideas from your basket   | 3 %     | 9 %      | 26 %     | 62 %    | indifferent    |

Note: households with an allergy (n = 38): flag must-be 74 %.
Decisions: flag = basic, keep it working; approvals = invest; live update = Q2 bet;
recipes = park (see "Saying no").

tools: any survey tool (Typeform, Google Forms, an in-app survey such as Sprig or Hotjar) and a spreadsheet to classify answers. Kano analysis templates exist for Excel and Miro.

4Gains vs losses nothing is free

What we gain

  • Customers settle the argument, not taste.
  • Basics get fixed first, before delighters.
  • A shared vocabulary: must-be, performance, attractive.
  • Wasted work avoided: indifferent features get dropped.
  • Segments show up: allergy households differ.

What we lose

  • Survey effort: questions, reach, analysis.
  • Hypothetical answers: people describe, not behave.
  • Categories drift: today's delighter is tomorrow's basic.
  • Hard to explain the two-question method at first.

6Common pitfalls the usual ways this goes wrong

  • One question only

    “Would you like this?” Everyone says yes. Fix → ask both: if it's there, and if it's not.

  • Celebrating basics

    A launch party for the flag. Fix → must-bes are fixed quietly; save the fanfare for performance and attractors.

  • Ignoring segments

    The average hides allergy households. Fix → split results by segment when it matters.

  • Surveying once forever

    2026's delighter is 2028's must-be. Fix → repeat yearly for the features that matter.

7When to use it (and when not)

Use it when…

  • When people argue about what customers value.
  • Planning a release with basics and extras.
  • Before investing in a “delighter”.
  • Checking if old delighters have become basics.

Skip it when…

  • When you can test real behaviour cheaply (an A/B test or fake door is better).
  • Features customers can't imagine yet.

8Self-check quiz

What are the two Kano questions?

How would you feel if the feature were there? And if it weren't?

What's a must-be feature?

One customers expect: missing it causes dissatisfaction, having it pleases nobody.

What happened to recipe ideas?

62 % indifferent: most customers don't care, so they were parked.

Why do categories change over time?

Customers get used to delighters; they become performance, then must-be.

try it

Pick four features your team disagrees about. Write the two Kano questions for each and send them to 50 customers (or 10, if that's what you can get). Classify the answers and bring the table to the next planning meeting before anyone gives an opinion.

remember!!

Fix the clean sheets first. Then the wi-fi. Then a note or two.
