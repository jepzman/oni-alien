Appendix

D

Glossary

All 70 key terms from the book's chapters, in one place. Each entry links to the chapter that explains it properly.

A · C · D · E · F · G · H · I · J · K · L · M · N · O · P · # · Q · R · S · T · U · Z

A

ACL
An access control list: extra permission entries for named users and groups on a file or directory. Ch. 4
Atomic operation
A change that happens completely or not at all, with no in-between state visible to others; renaming within a filesystem is atomic. Ch. 3

C

cloud-init
The program on cloud images that configures a new instance at first boot from its user data. Ch. 1
copytruncate
A logrotate method that copies a log and truncates the original, so a program can keep writing to the same open file. Ch. 7
cron
The traditional scheduler that runs commands from crontab files at given times. Ch. 6

D

Distribution
A kernel, a userland and a package manager released and supported together, such as Ubuntu or Debian. Ch. 1
Drop-in
A small .conf file in a unit's .d/ directory that overrides or adds settings. Ch. 6

E

Enabled
Hooked into a target so that the unit starts automatically at boot. Ch. 6
Exit status
The number a program returns when it finishes; 0 means success. Ch. 2
Expansion
The shell's rewriting of a word before running a command: variables, command substitution, arithmetic, word splitting and globbing. Ch. 2

F

FHS
The Filesystem Hierarchy Standard: the conventional layout of directories on Linux. Ch. 3
File descriptor
A small number a process uses to refer to an open file, pipe or socket. Ch. 2
fork and exec
The two steps that start a program: copy the current process, then replace the copy's program. Ch. 5

G

Globbing
Turning a word containing *, ? or […] into the list of matching file names. Ch. 2
Graceful shutdown
Stopping a server so it accepts no new work, finishes work in progress, and exits cleanly. Ch. 5
Group
A numbered set of users that can be given access together. Ch. 4

H

Hard link
An additional directory entry pointing to the same inode. Ch. 3
Hold
A mark that stops the package manager upgrading a package. Ch. 8

I

Image
A ready-made disk with an operating system installed, from which cloud VMs are launched. Ch. 1
initramfs
A small temporary filesystem the kernel uses at boot to find and mount the real root filesystem. Ch. 1
Inode
The record of a file's type, owner, permissions, size, times and data location; everything except its name. Ch. 3

J

Journal
journald's indexed, structured store of log entries, read with journalctl. Ch. 7
journald
systemd's logging service, which collects services' output, syslog messages and kernel messages into the journal. Ch. 7

K

Kernel
The program that runs the hardware and provides processes, memory, files, networking and permissions to everything else. Ch. 1

L

Log rotation
Periodically moving a log aside, starting a new one, compressing and eventually deleting old ones. Ch. 7
Log shipping
Sending copies of logs from a server to a central service where they are stored and searched. Ch. 7
LTS
Long-term support: a release meant to be run for years, with security updates for all of that time. Ch. 1

M

Mount point
The directory where another filesystem is attached to the tree. Ch. 3

N

needrestart
A tool that finds processes still using replaced libraries after an upgrade, and lists or restarts them. Ch. 8

O

Orphan
A process whose parent has exited; it is adopted by PID 1. Ch. 5

P

Package
An archive of files with metadata (name, version, dependencies) and install scripts, such as a .deb or .rpm. Ch. 8
PATH
The list of directories the shell searches, in order, to find a program by name. Ch. 2
Permission bits
Read, write and execute for a file's owner, its group and everyone else. Ch. 4
Pet
A server built and repaired by hand, which can't easily be replaced; the opposite of cattle, built from a description. Ch. 1
PID
The number the kernel uses to identify a process; PID 1 is the first process, the init system. Ch. 5
Pipe
A connection from one program's standard output to another's standard input, written |. Ch. 2
Pocket
One part of an Ubuntu release's repository: the release itself, -security, -updates or -backports. Ch. 8
Priority
A log entry's severity, from 0 (emerg) to 7 (debug). Ch. 7
Process
A running instance of a program, with its own PID, memory, open files and state. Ch. 5

#

/proc
A filesystem generated by the kernel that shows processes and kernel state as files. Ch. 3

Q

Quoting
Switching off expansions: single quotes switch off all of them, double quotes all but variables and command substitution. Ch. 2

R

Redirection
Connecting a program's standard stream to a file instead of the terminal, with >, >>, 2> or <. Ch. 2
Release
A numbered version of a distribution whose packages receive fixes, not major changes, until its end of support. Ch. 1
Repository
A server that publishes packages and a signed index of them for one or more releases. Ch. 8
Restart loop
A service that fails at start and is restarted repeatedly by its restart policy. Ch. 6
Root directory
The top of the single filesystem tree, written /. Ch. 3

S

Service manager
The program (systemd on most servers) that starts, supervises, restarts and stops services. Ch. 6
setgid (directory)
A directory bit that makes new entries inherit the directory's group. Ch. 4
Shell
The program that reads commands, expands them and runs programs; usually bash on servers. Ch. 2
Signal
A numbered notification the kernel delivers to a process, such as SIGTERM or SIGKILL. Ch. 5
Signal handler
Code a program registers to run when it receives a particular signal. Ch. 5
Signing key
The public key a package manager uses to verify that a repository's index was published by its owner. Ch. 8
Standard streams
The three channels every program starts with: standard input (0), standard output (1) and standard error (2). Ch. 2
Sticky bit
A directory bit that lets only a file's owner (or root) delete or rename it. Ch. 4
sudo
A program that lets permitted users run commands as root (or another user), with logging, according to rules in sudoers. Ch. 4
Symbolic link
A small file containing a path to another file or directory; also called a symlink. Ch. 3
Syslog
The traditional Unix logging interface and protocol; on Ubuntu, rsyslog writes it to text files in /var/log. Ch. 7
System call
A request from a program to the kernel, such as opening a file or starting a program. Ch. 1
systemd
The init system (PID 1) on most distributions; it starts and supervises services. Ch. 1

T

Target
A unit that groups other units into a milestone, such as multi-user.target. Ch. 6
Timer
A systemd unit that starts another unit on a schedule or after a delay. Ch. 6

U

UEFI
The firmware on modern machines that checks hardware and starts the bootloader. Ch. 1
UID
The number that identifies a user to the kernel; 0 is root. Ch. 4
umask
A per-process mask of permission bits removed from every new file and directory. Ch. 4
unattended-upgrades
Ubuntu and Debian's service that installs updates automatically, by default security updates only. Ch. 8
Unit
Anything systemd manages, described by a unit file: a service, timer, target, socket, mount or path. Ch. 6
Unit file
The text file that describes a unit, in sections such as [Unit], [Service] and [Install]. Ch. 6
User
An identity the kernel knows by its user ID (UID); processes run as a user and files are owned by one. Ch. 4
Userland
Everything outside the kernel: init, shells, utilities, libraries and applications. Ch. 1

Z

Zombie
A finished process whose exit status hasn't yet been collected by its parent. Ch. 5
