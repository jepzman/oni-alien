Appendix

D

Glossary

All 183 key terms from the book's chapters, in one place. Each entry links to the chapter that explains it properly.

A · B · C · D · E · F · G · H · I · J · K · L · M · N · O · P · R · S · T · V · W

A

ABAC
Attribute-based access control: rules over attributes of principal, resource, action and context. Ch. 6
Access control matrix
Principals × resources, with permitted actions in each cell. Ch. 6
Access entry
An EKS mapping from an IAM principal to Kubernetes permissions. Ch. 16
Access inventory
A list of every kind of principal, how it authenticates, what it can reach and who owns it. Ch. 25
Access review
A periodic confirmation of who has access, by someone who knows. Ch. 13
Access token
A short-lived token sent to APIs. Ch. 3
Accountability
Recording who did what, when, so actions can be traced to identities. Ch. 1
Account assignment
A user or group, a permission set and an account. Ch. 12
Account ID
The 12-digit number identifying an account, part of every ARN. Ch. 7
ACL
Access control list: the permissions stored on one resource. Ch. 6
ACS URL
Assertion consumer service: the SP endpoint that receives SAML responses. Ch. 5
Action
One API operation, written service:Operation. Ch. 9
Alternate contacts
Billing, operations and security contacts AWS uses for notices. Ch. 7
ARN
Amazon Resource Name: the unique identifier of an AWS resource. Ch. 9
Assertion
A signed SAML statement about a subject's authentication and attributes. Ch. 5
AssumeRoleWithWebIdentity
The STS call that exchanges an OIDC token for role credentials. Ch. 17
Attributes for access control
Identity attributes passed into sessions as tags, for ABAC. Ch. 12
Audience
The service a token is meant for; others must reject it. Ch. 3
Authentication
Proving a claimed identity with a credential. Ch. 1
Authorisation
Deciding whether an authenticated principal may perform an action on a resource. Ch. 1
Authoriser
The component that authenticates callers in front of an API. Ch. 19
Authorization code
A short-lived, one-time reference exchanged for tokens on the back channel. Ch. 4
Authorization server
Authenticates the user, collects consent and issues tokens. Ch. 4
AWS access portal
The page where people sign in and choose an account and permission set. Ch. 12
AWS account
A container for resources, identities and billing, isolated from other accounts. Ch. 7
AWS Organization
A group of accounts under central management, billing and policy. Ch. 20
aws:PrincipalArn
The ARN of the calling user or role (a role session's role), used for exceptions. Ch. 10
aws:PrincipalOrgID
The organisation of the calling principal. Ch. 22
AWS RAM
Resource Access Manager: shares resources across accounts and OUs. Ch. 21
aws:ResourceOrgID
The organisation that owns the resource being accessed. Ch. 22
aws:SourceArn / aws:SourceAccount
Condition keys naming the resource or account a service acts for. Ch. 21
aws:SourceOrgID
The organisation of the resource an AWS service is acting for. Ch. 22
aws:SourceVpc / aws:SourceVpce
The VPC or VPC endpoint a request came through. Ch. 22
aws:ViaAWSService
True when an AWS service makes a request on a principal's behalf. Ch. 22

B

Bearer token
A token that grants access to whoever presents it. Ch. 3
Birthright access
Access granted automatically from attributes such as department. Ch. 13
Break-glass access
Emergency access that works when normal sign-in doesn't. Ch. 14

C

Canonical request
The normalised form of a request that gets hashed and signed. Ch. 19
Centralised root access
Removing member accounts' root credentials and doing root tasks through scoped sessions. Ch. 7
check-access-not-granted
An Access Analyzer check that a policy doesn't allow listed actions or resources. Ch. 24
check-no-new-access
An Access Analyzer check that a new policy version grants nothing the old one didn't. Ch. 24
Claim
A statement in a token, such as sub, aud or exp. Ch. 3
Client
The application requesting access; confidential (can keep a secret) or public. Ch. 4
CloudTrail
AWS's record of API calls in an account. Ch. 11
Code owners
People or teams whose approval a repository requires for changes to given paths. Ch. 24
Condition key
A value AWS knows about a request, compared in a condition block. Ch. 9
Confused deputy
A privileged service tricked into acting for someone without that privilege. Ch. 21
Credential
What a principal shows to authenticate: a password, key, token or certificate. Ch. 1
Credential provider chain
The order in which tools look for credentials. Ch. 8
Credential report
A CSV of every IAM user and root, with password, MFA and access key status. Ch. 7
Credential scope
Date, region and service that a SigV4 signature is valid for. Ch. 19
Credential stuffing
Logging in with username–password pairs leaked from other sites. Ch. 2
Cross-account role
A role whose trust policy names a principal in another account. Ch. 21

D

Data event
A data-plane call such as S3 object access; recorded only if a trail asks for it. Ch. 11
Data key
A key generated per object or batch to encrypt data locally. Ch. 18
Data perimeter
Preventive guardrails ensuring only trusted identities reach trusted resources from expected networks. Ch. 22
Default deny
The rule that anything not explicitly allowed is denied. Ch. 1
Delegated administrator
A member account allowed to run an organisation-wide service. Ch. 20
Deploy-time least privilege
Giving a pipeline only the permissions a deployment needs. Ch. 17
Deprovisioning
Deactivating or deleting a person's accounts and access. Ch. 13
Discovery
The /.well-known/openid-configuration document describing a provider. Ch. 4
Drift
A difference between what the code says and what exists. Ch. 24

E

EKS Pod Identity / IRSA
Two ways to give a service account its own IAM role. Ch. 16
Elevation
Activating eligible privilege, with justification and often approval. Ch. 14
Eligibility
Being allowed to request a privilege, without holding it. Ch. 14
Encoded authorization message
A denial's details in encoded form, decoded with sts:DecodeAuthorizationMessage. Ch. 11
Encryption context
Key–value pairs bound to an encryption, required to decrypt and logged. Ch. 18
Envelope encryption
Encrypting data with a data key and the data key with a KMS key. Ch. 18
Explicit deny
A matching Deny statement in any policy; always wins. Ch. 10
External ID
A vendor-generated, per-customer value required in a trust policy. Ch. 21

F

Federation
Accepting another system's authentication of a person. Ch. 5
FullAWSAccess
The default SCP that allows everything through a level. Ch. 20

G

Grant
A temporary, narrow permission on a KMS key, usually created by a service. Ch. 18
GuardDuty
AWS's managed threat detection service. Ch. 23
Guardrail
A deny that holds regardless of other permissions. Ch. 10

H

Home realm discovery
Working out which IdP a person belongs to. Ch. 5
Hop limit
How many network hops IMDSv2's token response may travel. Ch. 15

I

IAM Access Analyzer
The AWS tool that validates policies and generates them from activity. Ch. 9
IAM group
A set of IAM users sharing policies; not a principal. Ch. 8
IAM Identity Center
AWS's workforce sign-in service for accounts and applications. Ch. 12
IAM OIDC identity provider
The IAM resource that tells AWS to trust an issuer's tokens. Ch. 17
iam:PassRole
The permission to give a role to an AWS service. Ch. 8
IAM role
An identity without credentials, assumed for temporary sessions. Ch. 8
IAM Roles Anywhere
Role sessions for workloads outside AWS, authenticated with X.509 certificates. Ch. 15
IAM user
A long-lived identity with a password and/or access keys in one account. Ch. 8
Identification
Claiming an identity, such as a user name. Ch. 1
Identity as code
Managing roles, policies and assignments as reviewed files that a pipeline applies. Ch. 24
Identity-based policy
A policy attached to a user, group or role. Ch. 9
Identity provider (IdP)
A system that authenticates principals and issues tokens describing them. Ch. 1
Identity source
Where Identity Center's users and groups come from. Ch. 12
ID token
An OIDC JWT, addressed to the client, describing the authentication. Ch. 4
IMDSv2
The session-oriented metadata service: PUT for a token, then token on each request. Ch. 15
Implicit deny
The default result when nothing allows a request. Ch. 10
Instance metadata service
The link-local endpoint that serves an instance's details and role credentials. Ch. 15
Instance profile
The container that attaches a role to an EC2 instance. Ch. 15
invokedBy
The service that made a call on a principal's behalf. Ch. 11

J

JIT provisioning
Creating an account at a person's first federated sign-in. Ch. 5
Joiner, mover, leaver
The three lifecycle events that change a person's access. Ch. 13
Just-in-time access
Privilege activated for a limited time when needed. Ch. 14
JWKS
JSON Web Key Set: an issuer's published public keys. Ch. 3
JWT
JSON Web Token: base64url-encoded header and claims, plus a signature. Ch. 3

K

Key policy
The resource-based policy that controls a KMS key. Ch. 18
KMS key
A key held in AWS KMS's hardware, used to wrap data keys or encrypt small data. Ch. 18
Kubernetes RBAC
Kubernetes' allow-only, role-based authorisation for its API. Ch. 16

L

Last accessed information
Which services and actions an identity has actually used, and when. Ch. 11
Least privilege
Only the access needed, for only as long as needed. Ch. 6

M

Managed / inline policy
A standalone, reusable policy, versus one embedded in a single identity. Ch. 9
Management account
The account that creates and pays for an AWS Organization. Ch. 7
Management event
A control-plane call (create, change, delete, many reads); recorded by default. Ch. 11
Metadata
An XML description of an IdP or SP: entity ID, endpoints and certificates. Ch. 5
MFA
Multi-factor authentication: two or more different kinds of factor. Ch. 2
Mutual TLS
TLS where the client also presents a certificate. Ch. 19

N

NameID
The identifier for the subject; persistent NameIDs never change for a person and SP. Ch. 5
Node role
The IAM role of an EKS worker node. Ch. 16

O

OAuth 2.0
A framework for granting applications limited access to resources on a user's behalf. Ch. 4
OIDC federation
Trusting tokens from an external OpenID Connect issuer to grant role sessions. Ch. 17
OpenID Connect
An identity layer on OAuth 2.0 that adds sign-in and ID tokens. Ch. 4
Organisational unit (OU)
A container of accounts to which policies attach. Ch. 20
Organisation instance
An Identity Center instance in an organisation, able to grant AWS account access. Ch. 12
Organisation trail
A CloudTrail trail recording every account in an organisation. Ch. 23
Origin
The scheme, host and port of a web page, such as https://larder.example. Ch. 2

P

Passkey
A FIDO2/WebAuthn credential: a per-site key pair whose private key stays on the user's device or keychain. Ch. 2
Password hashing function
A deliberately slow, often memory-hard hash such as Argon2id, scrypt or bcrypt. Ch. 2
PEP / PDP
Policy enforcement point (blocks the request) and policy decision point (decides). Ch. 1
Permissions boundary
A managed policy that caps an identity's maximum permissions. Ch. 10
Permission set
A template of policies and session length that becomes a role in each assigned account. Ch. 12
Phishing-resistant
An authenticator whose output can't be relayed to a site other than the one it was made for. Ch. 2
Pilot light
A minimal copy of critical systems in another region, ready to be scaled up in a disaster. Ch. 25
PKCE
Proof Key for Code Exchange: a secret verifier that proves the redeemer of a code started the flow. Ch. 4
Policy
A JSON document of statements that allow or deny actions on resources. Ch. 9
Policy engine
A component that evaluates authorisation rules and returns allow or deny. Ch. 6
Policy generation
Drafting a policy from a role's recorded activity in CloudTrail. Ch. 24
Policy simulator
AWS's tool for evaluating a principal's policies against chosen requests. Ch. 11
Policy variable
A ${…} placeholder filled in from the request at evaluation time. Ch. 9
Principal
A person or workload that can make requests and be granted access. Ch. 1
Principal tag / resource tag
Key-value pairs on an identity or a resource, used for ABAC. Ch. 9
Privilege creep
Access accumulating over time as people move and cover. Ch. 6
Privileged access
Permissions that can cause serious harm or grant more access. Ch. 14
Projected token
A short-lived, audience-bound service account JWT mounted into a pod. Ch. 16
Protected environment
A GitHub environment with deployment rules such as required reviewers. Ch. 17
Provisioning
Creating, updating and removing accounts and group memberships in apps. Ch. 13

R

RBAC
Role-based access control: permissions granted to roles, roles assigned to principals. Ch. 6
RCP
Resource control policy: an organisation ceiling on access to resources in member accounts. Ch. 10
ReBAC
Relationship-based access control: decisions follow relationships between objects. Ch. 6
Refresh token
A longer-lived, revocable token used only to get new access tokens. Ch. 3
Replay
Re-sending a captured, valid request. Ch. 19
Resource-based policy
A policy attached to a resource, naming the principals that may use it. Ch. 9
RoleBinding / ClusterRoleBinding
Grants of a role to subjects in a namespace / everywhere. Ch. 16
Role / ClusterRole
Rules within a namespace / cluster-wide (or reusable). Ch. 16
Role explosion
Roles multiplying because they encode extra dimensions such as location. Ch. 6
Role session
A period of use of a role, with its own ARN and temporary credentials. Ch. 8
Root user
The account's original email-and-password identity, with unrestricted access. Ch. 7
Rotation
Issuing a new refresh token at each use, and treating reuse as theft. Ch. 3

S

S3 Object Lock
Write-once storage that prevents deletion before a retention date. Ch. 23
Salt
A random per-password value hashed with it, so identical passwords give different hashes. Ch. 2
SCIM
A standard REST API for provisioning users and groups. Ch. 13
Scope
A named slice of access a client requests and a token carries. Ch. 4
SCP
Service control policy: an organisation ceiling on principals in member accounts. Ch. 10
Secrets Manager
AWS's service for storing and rotating secrets. Ch. 18
Separation of duties
Splitting sensitive tasks so no one person can complete them alone. Ch. 6
Service account
A pod's identity for the Kubernetes API, and the anchor for its cloud role. Ch. 16
Service provider (SP)
The application that relies on the IdP's assertions. Ch. 5
Service role
A role an AWS service assumes to act for you. Ch. 8
Session
The state that lets a server recognise later requests after one authentication. Ch. 3
Session policy
A policy passed at session creation that narrows a role session. Ch. 10
Session theft
Stealing an authenticated session's cookie or token, skipping passwords and MFA. Ch. 25
SigV4
AWS Signature Version 4: HMAC signing of API requests with derived keys. Ch. 19
Source identity
An unchangeable value recorded for every action in a session and its chained sessions. Ch. 8
Source of truth
The system whose record decides; for people, usually HR. Ch. 13
SSRF
Server-side request forgery: making a server send requests on an attacker's behalf. Ch. 15
Standing access
Privilege held permanently, whether used or not. Ch. 14
Statement
One rule in a policy: effect, actions, resources and optional conditions. Ch. 9
STS
AWS Security Token Service, which issues temporary credentials. Ch. 8
sub claim
The token's subject; for GitHub, the repository plus branch, environment or pull request. Ch. 17

T

Tabletop exercise
Walking through an incident scenario on paper to find gaps. Ch. 25
Task role / execution role
An ECS task's role for its code, and the ECS agent's role for starting it. Ch. 15
TOTP
Time-based one-time password: an HMAC of the current 30-second step and a shared secret. Ch. 2
Trust policy
The resource-based policy on a role that says who may assume it. Ch. 8
Two-person rule
Requiring two people for an action, not just for its approval. Ch. 14

V

Vault lock
An AWS Backup setting that stops anyone deleting backups before their retention ends. Ch. 21

W

Watch list
The short set of events that raise alerts, each with a response. Ch. 23
Webhook
An HTTP callback a partner sends to report an event. Ch. 19
Workload identity
The identity software uses to call cloud APIs. Ch. 15
