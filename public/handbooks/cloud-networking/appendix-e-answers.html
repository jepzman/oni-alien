Answers to the exercises

Every “check your understanding” question in the book, with its worked answer. Try each question in its chapter first; come here to check.

1What happens when you open a web page

  1. Put these in the order they happen when you open https://www.larder.example: TLS handshake, DNS lookup, HTTP request, TCP connection.

    DNS lookup, TCP connection, TLS handshake, HTTP request. Each needs the one before: you can't connect without an address, and you can't encrypt without a connection.

  2. As a packet travels from the laptop to the server, which of these change at each router: the source MAC address, the destination IP address, the destination port?

    Only the MAC addresses change at every hop, because each frame is for one link only. The destination IP address and port stay the same end to end, unless a NAT device rewrites them on purpose.

  3. A colleague's API call fails with Connection refused. Another says it must be a firewall. Are they likely right?

    Probably not. A refusal is an answer from the target machine, so the packets got there. Most cloud firewalls drop packets silently, which gives a timeout. Check whether the program is running and listening on the right port and address.

  4. A page makes four round trips before content starts to arrive. How long does that take at minimum for a user in Sydney if the servers are in Frankfurt? What are two ways to improve it?

    At about 280 ms per round trip, roughly 1.1 seconds. Improvements: fewer round trips (TLS 1.3, connection reuse, HTTP/3), or serving content from closer to the user with a CDN or a second region.

  5. Why does the internet cut data into packets instead of reserving a line for each conversation, like old telephone networks?

    Packets let many conversations share the same links, use capacity only when there is data to send, resend only the pieces that were lost, and route around failures in the middle of a conversation.

2IP addresses and CIDR without fear

  1. How many addresses are in a /21, and how many could you use for servers on AWS?

    232−21 = 211 = 2,048 addresses, of which 2,043 are usable on AWS (5 are reserved).

  2. Which /20 network contains 10.20.200.9? Give its first and last address.

    Blocks of 16 in the third octet: 200 rounds down to 192. So 10.20.192.0/20, from 10.20.192.0 to 10.20.207.255.

  3. Do 10.8.0.0/14 and 10.10.0.0/16 overlap?

    Yes. A /14 is a block of 4 in the second octet, so 10.8.0.0/14 covers 10.8 to 10.11, which includes all of 10.10.0.0/16.

  4. A teammate proposes subnets 10.20.0.0/24, 10.20.1.0/24 and 10.20.2.0/20. What's wrong, and how would you fix it?

    10.20.2.0/20 isn't aligned: a /20 must start at a multiple of 16 in the third octet, so it's really 10.20.0.0/20, which overlaps the two /24s. Place the /20 at 10.20.16.0/20, or allocate the /20 first and put the /24s elsewhere.

  5. Why can't you just create a /16 for every team and stop worrying about addresses?

    You can, if they come from a plan that keeps them from overlapping each other and your offices. 10.0.0.0/8 holds 256 /16s, which is plenty for most companies, but only if they're handed out centrally. The danger isn't size, it's two teams picking the same range and later needing to connect.

  6. An IPv6-only server in a public subnet has no NAT in front of it. How do you stop the internet from reaching it while still letting it download updates?

    With routing and firewalls, not NAT. On AWS, route its IPv6 default route through an egress-only internet gateway, which allows outbound connections and their replies but nothing inbound, and keep its security group closed to inbound traffic.

3TCP, UDP and ports

  1. Write the 5-tuple of the reply packet for a request TCP 10.20.17.8:51544 → 10.20.64.12:5432.

    TCP 10.20.64.12:5432 → 10.20.17.8:51544. Source and destination swap, ports included.

  2. Calls to a new service fail instantly with Connection refused. The security group allows the port. What do you check first?

    The service itself: is it running, on that port, and listening on an address other than 127.0.0.1? A refusal means the packets arrived, so the security group and routes aren't the problem.

  3. A network ACL allows inbound TCP 443 and outbound TCP 443. Web requests from the internet to a server behind it time out. Why?

    Network ACLs are stateless. Replies go from the server's port 443 to the client's ephemeral port, so the outbound rule must allow destination ports 1024–65535, not 443.

  4. Why does DNS use UDP, and when does it fall back to TCP?

    A DNS lookup is one small question and one small answer, so a handshake would double its time; a lost packet is simply asked again. Answers too large for a UDP response (common with DNSSEC or many records) are retried over TCP, so both must be allowed.

  5. A worker keeps a database connection open through an AWS Network Load Balancer and is idle for ten minutes between jobs. What will happen, and what are two fixes?

    The load balancer forgets the connection after 350 seconds, and the worker's next query gets a reset. Fixes: close and reopen connections when idle for less than 350 seconds (or validate them before use), or enable TCP keepalives with an interval under 350 seconds. Raising the load balancer's timeout also helps.

4Routing: how packets find their way

  1. A route table holds 10.0.0.0/8 → A, 10.20.0.0/16 → B, 10.20.0.0/20 → C and 0.0.0.0/0 → D. Where do packets to 10.20.15.1, 10.20.16.1 and 10.21.0.1 go?

    10.20.15.1 is in 10.20.0.0/20 (0–15), so C. 10.20.16.1 is outside that /20 but in the /16, so B. 10.21.0.1 only matches the /8 and the /0, so A.

  2. Why does adding a route for 0.0.0.0/0 at the top of a table not send all traffic through it?

    Order doesn't matter: the longest matching prefix wins, and a /0 is the shortest possible, so every more specific route beats it.

  3. Requests from a new office reach a cloud server, but the office sees timeouts. The office router has a route to the VPC. What do you check next, and where?

    The return path: the route table of the server's subnet, and of every gateway on the way back (transit gateway, VPN), for a route that covers the office's range. Then any firewall on the return path, in case it's stateless or asymmetric.

  4. Two VPN tunnels connect a store to Frankfurt for redundancy. Why is BGP better than static routes here?

    With BGP, when one tunnel fails its session drops and its routes are withdrawn, so traffic moves to the other tunnel within seconds, automatically. New ranges are also advertised without editing tables. With static routes, a failed tunnel can keep attracting traffic until someone changes the routes.

  5. Traffic between two VPCs is sent through an inspection firewall in a third VPC. Connections sometimes hang. What would you suspect, and what's a fix?

    Asymmetric routing: the request and the reply pass through different firewall instances (or one direction bypasses the firewall), so a stateful firewall sees only half the connection. Fix the routes so both directions go through the same appliance, for example with Transit Gateway appliance mode.

5DNS: the internet's address book

  1. Why can't larder.example itself be a CNAME to a load balancer, and what do you use instead?

    The zone apex must hold NS and SOA records, and a CNAME can't share its name with any other record. Use an alias record (Route 53) or ALIAS/ANAME (other hosts), which answers with the load balancer's current addresses.

  2. A record has a TTL of 86,400 seconds. You change it at 10:00. When can you be sure every well-behaved resolver sees the new value?

    Not until 10:00 the next day: a resolver that cached it just before the change may keep it for a full day. Lowering the TTL to 60 a day ahead would have made it about a minute.

  3. dig on an instance shows the new address, but the application on that instance keeps calling the old one. Name two possible causes.

    The application caches DNS itself (for example, resolving once at startup or a runtime that caches indefinitely), or it holds long-lived connections opened before the change. Others: an entry in /etc/hosts, or the app using a different resolver than dig.

  4. An instance resolves db.internal.larder.example fine, but a new VPC's instances get NXDOMAIN. What's the likely cause?

    The private hosted zone isn't associated with the new VPC (or the VPC's DNS resolution and hostnames settings are off). Private zones answer only inside the VPCs they're attached to.

  5. You need to fail over a public website from Frankfurt to a standby region. Why is a DNS failover record a reasonable choice, and what's its main limitation?

    It's simple, cheap and works across regions and providers, with health checks deciding the answer. Its limitation is caching: clients switch over only as cached answers expire, so with short TTLs failover takes minutes, and clients that ignore TTLs may not switch at all.

6HTTP, TLS and certificates

  1. A load balancer returns 503 for every request, while the servers' own logs show nothing at all. What's the most likely cause?

    The load balancer has no healthy targets, so it isn't forwarding anything. Check the health checks: path, port and expected status, and whether the servers' security groups allow the load balancer's health check traffic.

  2. Does a certificate for *.larder.example cover larder.example and eu.shop.larder.example?

    Neither. A wildcard covers exactly one label in place of the *: shop.larder.example yes, the bare domain and deeper names no. Add them as separate SANs.

  3. Why can a browser show a padlock for a server whose chain is incomplete, while curl or a Java client fails?

    Browsers cache intermediates from other sites and can fetch missing ones from the URL in the certificate. Most programmatic clients only use what the server sends plus their root store, so they can't complete the chain.

  4. A compliance rule says traffic must be encrypted on every network hop, and you also need path-based routing and a WAF. Which TLS option do you choose?

    Re-encryption: terminate at a layer 7 load balancer (so it can route on paths and apply the WAF), then open a new TLS connection to the targets, with certificates on the targets from a private CA.

  5. What does an observer on the network path still learn about an HTTPS request?

    The client and server IP addresses and ports, the timing and size of the traffic, and usually the server name, which is sent in the clear as SNI (unless Encrypted Client Hello is used). Not the path, headers or body.

7Regions, zones and the shape of a cloud network

  1. What's the difference between a region and an availability zone, and which one is a VPC tied to on AWS?

    A region is a separate geographic area; a zone is an independent group of data centres inside it. An AWS VPC belongs to one region and spans all its zones; each subnet sits in one zone.

  2. Two services exchange 50 TB a month, and they run in different zones. Roughly what does that cost on AWS, and what would you change?

    At about $0.01 per GB in each direction, 50 TB ≈ 50,000 GB, so roughly $500 for one direction and up to $1,000 if both sides are counted. Make the calls zone-local where possible: same-zone replicas or caches, zone-aware routing, or co-locating the two services in each zone.

  3. A clustering tool that discovers peers by broadcast works in your data centre but not in a VPC. Why?

    A VPC is an overlay that delivers each packet to a specific host; there's no broadcast (and no multicast without Transit Gateway). Use the tool's cloud discovery option, such as tags, DNS or a registry.

  4. You and a partner both deploy an endpoint “in eu-central-1a” to keep traffic in one zone. Traffic is still charged as cross-zone. Why?

    Zone names are mapped per account, so your 1a and the partner's 1a can be different zones. Align on zone IDs such as euc1-az2.

  5. Name three networking responsibilities that stay with you, not the provider.

    Any three of: the address plan, route tables, firewall rules, what is exposed to the internet, encrypting your traffic end to end, and designing for zone or region failure.

8Inside a VPC: subnets, route tables and gateways

  1. A server sits in a subnet whose route table sends 0.0.0.0/0 to an internet gateway, but the server has no public IP. Can it download a package from the internet?

    No. The internet gateway only translates for resources that have a public or Elastic IP. Without one, the packet has a private source address the internet can't reply to. Give it a public IP, or better, move it to a private subnet that goes out through a NAT gateway.

  2. A route table has 10.20.0.0/16 → local, 10.0.0.0/8 → tgw and 0.0.0.0/0 → nat. Where do packets to 10.30.4.4 and to 10.20.99.1 go?

    10.30.4.4 isn't in 10.20.0.0/16, so the longest match is /8: the transit gateway. 10.20.99.1 is inside the VPC range, so local wins, even if no subnet uses that address. The packet stays in the VPC and is dropped there.

  3. How many addresses can you use in a /26 subnet on AWS?

    59. A /26 has 64 addresses and AWS reserves 5.

  4. Give two reasons to run one NAT gateway per availability zone instead of one for the whole VPC.

    Resilience: a problem in one zone doesn't cut internet access for the others. Cost: traffic doesn't cross zones to reach the NAT gateway, so you don't pay cross-zone data charges.

  5. Your database subnet has no default route. Nightly backups to S3 now fail. What are two ways to fix it, and which would you choose?

    Add a default route to a NAT gateway, or add an S3 gateway endpoint to the subnet's route table. Choose the endpoint: it's free, keeps traffic on AWS's network, and keeps the subnet isolated from the internet.

  6. A colleague coming from AWS asks you to “create the public subnets” in Google Cloud. What do you explain?

    Google Cloud has no public subnets. Routes belong to the whole VPC network, and the default route to the internet gateway exists for every subnet. A VM is reachable when it has an external IP and a firewall rule allows the traffic. VMs without external IPs go out through Cloud NAT.

9Firewalls in the cloud: security groups and network ACLs

  1. Two servers in the same subnet can't talk. Which filters could be responsible: the security groups, the NACL, or both?

    Only the security groups. A NACL filters traffic crossing the subnet boundary, and this traffic never leaves the subnet.

  2. Why is “allow 5432 from sg-app” better than “allow 5432 from 10.20.16.0/20”?

    It follows the role, not the address: any interface with sg-app is allowed, wherever it gets its address, and nothing else in that range is. It doesn't need editing when servers move, scale or change subnet.

  3. You remove a rule and everything keeps working, so you close the change. An hour later a deploy fails to connect. What happened?

    The existing connections were tracked, so they stayed allowed after the rule was removed. The deploy started new processes that opened new connections, which the remaining rules don't allow.

  4. Write the inbound and outbound NACL rules a public subnet needs for a web server to serve HTTPS to the internet.

    Inbound: allow TCP 443 from 0.0.0.0/0. Outbound: allow TCP 1024–65535 to 0.0.0.0/0 for the replies. (If the server also makes outbound calls, add outbound 443 and inbound 1024–65535 for those replies.)

  5. A platform team wants a rule that no team can override: nothing may reach the data subnets except from the app subnets. Which tools would you use on AWS, Azure and Google Cloud?

    AWS: a NACL on the data subnets (managed centrally), or Firewall Manager policies. Azure: Virtual Network Manager security admin rules, which take precedence over NSGs. Google Cloud: a hierarchical firewall policy at the organisation or folder level.

10Planning your IP address space

  1. Larder opens stores in a seventh city. Using Table 10.2, which range do they get, and what changes in Frankfurt's route tables?

    The next /16 in 10.8.0.0/13 after the existing cities, for example 10.14.0.0/16 if six are used (10.8–10.13). Nothing changes in Frankfurt: the existing route for 10.8.0.0/13 already covers it, and with BGP the store's route is learned anyway. An eighth city still fits; a ninth would need a new block.

  2. Why divide by location before environment, rather than the other way round?

    Routing follows location: offices, stores and other regions reach a region through one path, so a single block per region keeps routes short. Dividing by environment first would scatter each region's VPCs across several blocks and need more routes everywhere.

  3. An EKS cluster in a /16 VPC is running out of addresses. Name two fixes that don't involve a new VPC.

    Any two of: add a secondary CIDR and new subnets for pods; give pods a non-routed range from 100.64.0.0/10 (custom networking); use prefix delegation to reduce waste; move pods to IPv6.

  4. A partner overlaps your production range and needs to call one API. Why is PrivateLink better than a VPN with NAT here?

    PrivateLink exchanges no routes, so overlap doesn't matter, and the partner can reach only that one service. A VPN with NAT works but is more complex, joins the networks more broadly, and needs translation rules maintained on at least one side.

  5. A colleague says “we're moving to IPv6, so we don't need an address plan”. What do you answer?

    Scarcity goes away, but you still need to know which prefix belongs to which VPC and region for routing, firewall rules, troubleshooting and summarisation. And you'll run IPv4 alongside for years, so its plan still matters.

11Connecting VPCs: peering, transit gateways and hubs

  1. VPC A is peered with B, and B has a NAT gateway. Can A's private instances use B's NAT gateway to reach the internet?

    No. Peering only carries traffic between the two VPCs themselves; it can't be used to reach B's gateways, VPNs or other peers.

  2. How many peering connections would a full mesh of 12 VPCs need, and how many TGW attachments?

    12 × 11 / 2 = 66 peerings; 12 attachments.

  3. Using Table 11.2, can development reach a store's handheld? Trace both directions.

    No. Development's attachment is associated with tgw-rt-nonprod, which only knows the hub, so packets to 10.8.0.0/13 are dropped at the TGW.

  4. Explain the difference between association and propagation in one sentence each.

    Association: the one TGW route table used to look up traffic arriving from an attachment. Propagation: the attachment automatically adds routes to itself into one or more TGW route tables.

  5. Two VPCs attached to the same TGW exchange 40 TB a month. What could you change to cut cost, and why does routing still work?

    Peer them directly as well. In each VPC's route table, keep a summary route such as 10.0.0.0/8 → tgw (as Larder's tables have) and add the other VPC's exact /16 with the peering as its target. Longest prefix match sends their traffic over the peering, which has no per-GB processing charge, while everything else still uses the TGW.

12Private access to cloud services

  1. A job in a subnet with no NAT can pull its image manifest from ECR but hangs downloading layers. What's missing?

    The S3 gateway endpoint: ECR stores image layers in S3, so ecr.api and ecr.dkr interface endpoints aren't enough on their own.

  2. Why can Korenwolf reach Larder's API with PrivateLink even though both use 10.20.0.0/16?

    No routes are exchanged. Korenwolf talks to an endpoint with an address in its own VPC, and PrivateLink carries the connection to Larder's NLB, which forwards it to targets in Larder's VPC. Neither network ever needs to route to the other's addresses.

  3. An endpoint has private DNS on. Will a server in a peered VPC resolve the service name to the endpoint?

    No. Endpoint private DNS answers only for the VPC the endpoint is in. The peered VPC gets the public address unless you associate a private hosted zone for the name with it (and turn the endpoint's own private DNS off, as in 12.5).

  4. What do a security group and an endpoint policy each control on an interface endpoint?

    The security group controls which network sources may connect to the endpoint. The endpoint policy controls which API actions on which resources may be performed through it, regardless of who connects.

  5. Your monitoring vendor offers a PrivateLink endpoint or a public HTTPS endpoint. Your servers already have NAT. When is the PrivateLink option worth paying for?

    When traffic is heavy (endpoint per-GB pricing beats NAT processing), when the sending subnets shouldn't have internet access, or when policy requires telemetry to stay off the internet. For light traffic from subnets that already have NAT, the public endpoint is fine.

13Hybrid connectivity I: site-to-site VPN and BGP

  1. Why does an AWS VPN connection have two tunnels, and what happens if you configure only one?

    The two tunnels end on two separate AWS devices, so one can fail or be taken down for maintenance while the other carries traffic. With only one configured, you lose connectivity whenever that one is down, including during routine AWS maintenance.

  2. SSH sessions over a new VPN work, but scp of a large file stalls right after starting. What do you suspect, and how do you confirm it?

    An MTU black hole: the interactive session uses small packets, the file transfer full-size ones. Confirm with a do-not-fragment ping across the tunnel at decreasing sizes (ping -M do -s 1472, then smaller) and find where replies start; fix with MSS clamping and by allowing ICMP “fragmentation needed”.

  3. A store has fibre and 4G, each with a VPN connection. How do you make sure AWS sends traffic over fibre while it's up?

    With BGP on both: have the store router prepend its ASN on the routes it advertises over the 4G connection, so AWS sees a longer AS path there and prefers the fibre path. When the fibre's sessions drop, only the 4G routes remain and traffic moves over.

  4. What does BGP give you over static routes in a VPN with many sites?

    New ranges are advertised and learned automatically, failed tunnels' routes are withdrawn so traffic fails over without human action, and preferences between paths can be expressed with attributes such as AS path length.

  5. Your company opens a data centre that will send 5 Gbps to AWS around the clock. Is a site-to-site VPN a good fit?

    Not on its own. One tunnel carries about 1.25 Gbps, so you'd need several connections with ECMP through a transit gateway; you'd depend on the internet's variable latency; and internet data transfer prices for that volume add up. A dedicated connection (Direct Connect) is the better primary path, with the VPN as backup.

14Hybrid connectivity II: dedicated connections

  1. Which virtual interface type would you use to reach VPCs in two regions through their transit gateways?

    A transit VIF to a Direct Connect gateway, with the DX gateway associated with each region's transit gateway.

  2. Why is “two connections at one Direct Connect location” not the high-resiliency design?

    Both share the building: a power failure, fire, flood or cut fibre into that location takes both down. High resiliency needs connections at two different locations.

  3. Your company moves 5 TB a month from AWS to its office. A sales rep proposes Direct Connect to save money. Is it likely to?

    Unlikely. At about $0.07 per GB saved, 5 TB saves roughly $350 a month, well below the fixed costs of a port or hosted connection, circuit and colocation. Other reasons (latency, policy) might still justify it, but cost alone doesn't.

  4. A regulator requires encryption on all links carrying customer data. Your 10 Gbps dedicated connection runs at 7 Gbps. Which encryption option fits, and why not the others?

    MACsec, if your location supports it: line-rate encryption with no throughput loss. IPsec over Direct Connect would need many tunnels at about 1.25 Gbps each to carry 7 Gbps. TLS in every application is good practice but may not satisfy a rule about the link itself.

  5. A Direct Connect link with a VPN backup fails over to the VPN, and everything slows to a crawl. What did the design miss?

    The backup's capacity. A VPN's tunnels carry far less than a dedicated link, so the design needed either more VPN capacity (several connections with ECMP), a second Direct Connect, or an agreed list of what may be paused or slowed during failover.

15DNS across clouds and data centres

  1. Why can't a store's router simply use the VPC resolver's address, 10.16.0.2, as its DNS server over the VPN?

    The VPC resolver only answers queries that originate inside the VPC. Traffic arriving from the VPN can't use it; an inbound endpoint provides addresses that can.

  2. Someone creates a private zone larder.example containing only api. What breaks, and where?

    Inside every VPC associated with the zone, every other larder.example name (www, hooks, mail records) returns NXDOMAIN, because the private zone replaces the public one there. Outside those VPCs nothing changes.

  3. A server in a VPC must resolve printer3.office.larder.example. List what you'd create.

    An outbound resolver endpoint (two subnets), a forwarding rule for office.larder.example targeting the office DNS server, an association of that rule with the server's VPC, and a route plus firewall rules allowing DNS from the endpoint to the office server over the VPN.

  4. Why forward only specific AWS service names, not all of amazonaws.com, from a site to an inbound endpoint?

    Only names that have interface endpoints with private DNS benefit; everything else would just resolve publicly through the cloud resolver instead of locally, adding a dependency on the VPN and the endpoint for every AWS lookup at the site.

  5. Design question: where should Larder's inbound and outbound endpoints live, and why?

    In the hub VPC, which every site reaches through the TGW and which is associated with every private zone. One pair of each serves all sites and VPCs; forwarding rules are shared with other accounts through RAM and associated with each VPC.

16Load balancers: layer 4 and layer 7

  1. A partner must allow-list your service's IP addresses in their firewall. Which load balancer do you put in front of it, and why?

    A Network Load Balancer with Elastic IPs: it has fixed addresses per zone. An ALB's addresses change over time, so it can't be allow-listed by IP. (If you also need HTTP routing, put the ALB behind the NLB.)

  2. Your health check calls the database. The database fails over, taking 40 seconds. What do users see, and what would you change?

    Every target fails its health check together; the ALB either fails open or, briefly, has no healthy targets, so users get errors or 503s even for pages that don't need the database. Make the health check shallow, and let the app handle the database outage (errors for affected requests, cached data, retries).

  3. Why do keep-alive 502s happen more at quiet times than at busy times?

    When it's busy, each connection is reused before the app's short keep-alive timeout expires, so the app never closes one. When it's quiet, connections sit idle long enough for the app to close them, and occasionally the load balancer sends a request on a connection at the moment it's being closed.

  4. Users report errors every time you deploy. The ALB's deregistration delay is 300 seconds. Where do you look?

    At the app's shutdown: it probably exits immediately on SIGTERM, dropping requests in flight, or the platform kills it before it finishes. Handle the signal, stop accepting new work, finish open requests, then exit, within the platform's stop timeout and the deregistration delay.

  5. Write the rules (priority, condition, action) for: api.larder.example to the API, /static/* to an S3-backed service, HTTP to HTTPS, everything else to the web app.

    On the :80 listener: default action redirect to HTTPS. On the :443 listener: priority 10, host header api.larder.example → forward to tg-api; priority 20, path /static/* → forward to the static target group; default → forward to tg-web. Host and path rules don't overlap here, but if they could, the lower priority number wins.

17The edge: CDNs, WAF and DDoS protection

  1. Which Cache-Control header would you send for app.3f9c2e.js, for the homepage, and for the basket page?

    public, max-age=31536000, immutable for the versioned file; something like public, s-maxage=60, max-age=0, stale-while-revalidate=30 for the homepage; private, no-store for the basket.

  2. At 5,000 requests per second, how much does raising the hit ratio from 95% to 99% reduce origin load?

    From 250 to 50 requests per second at the origin: a fivefold reduction from a four-point change.

  3. Your site is behind CloudFront, but the ALB's security group allows 443 from 0.0.0.0/0. Why is that a problem, and what are two fixes?

    Anyone who finds the ALB's address can bypass the cache, the WAF and the edge's DDoS absorption. Fixes: make the ALB internal and use a VPC origin; or allow only CloudFront's managed prefix list, plus a secret custom header the ALB checks.

  4. Why put a new WAF rule in count mode first?

    To see what it would block before it blocks anything: managed rules and patterns can match legitimate requests (unusual inputs, partner integrations), and blocking customers is an outage you caused.

  5. An attacker floods your login page with real HTTPS requests from 10,000 home routers. Which defences help, and which don't?

    Network-level DDoS protection doesn't help much: these are valid requests. Caching doesn't help either, since login can't be cached. What helps: WAF rate-based rules per IP and per other keys, bot-control and account-takeover managed rules, challenges such as CAPTCHAs, and keeping login on servers separate from checkout so the attack can't starve it.

18Controlling egress: NAT at scale, proxies and firewalls

  1. Why can't security groups alone restrict a server to “only the payment provider's API”?

    Security groups work on IP addresses, and the provider's API sits behind addresses that change and are shared with other services. Restricting by name needs DNS filtering, SNI-based firewall rules or a proxy.

  2. A DNS Firewall blocks bad.example. Malware on a server connects to 203.0.113.66:443 directly. What stops it?

    Not DNS Firewall: no lookup happens. A network firewall with an SNI/Host allow-list would drop it (the name won't be on the list), as would having no internet route at all. Security groups would only help if outbound traffic were restricted to known addresses.

  3. After centralising egress, connections from staging to the internet fail about half the time. What do you check first?

    Symmetric routing: whether appliance mode is on for the egress VPC's TGW attachment, and whether return routes in the NAT subnets send spoke ranges back through the same zone's firewall endpoint. A stateful firewall seeing only one direction drops the connection.

  4. Why build an inventory and run in alert mode before blocking?

    So you know every legitimate destination and its owner before anything is blocked; otherwise you break critical integrations. Alert mode shows what the rules would have blocked, so misses can be fixed without an outage.

  5. Your data tier needs Secrets Manager, KMS and S3, and nothing else. Design its egress.

    No internet route at all; an S3 gateway endpoint and interface endpoints for Secrets Manager and KMS with endpoint policies limited to your accounts; security groups allowing outbound 443 only to the endpoints' group and the S3 prefix list; DNS Firewall and query logging as a backstop.

19Containers and Kubernetes networking

  1. What's the maximum number of pods on a node with 4 ENIs of 15 addresses each, using the VPC CNI without prefix delegation?

    4 × (15 − 1) + 2 = 58 pods.

  2. Why can an ALB in IP mode send traffic straight to pods on EKS, but not on a cluster with an overlay CNI?

    With the VPC CNI, pod addresses are real VPC addresses that the VPC routes, so the ALB can reach them. With an overlay, pod addresses exist only inside the cluster; outside traffic must enter through nodes (NodePort) or a component on them.

  3. Pods in 100.64.0.0/16 call an API in another VPC over the transit gateway. What source address does that VPC see, and why does it matter?

    The node's address in the app subnet: the CNI translates pod traffic leaving the VPC. That's why the 100.64 range never needs routing outside the VPC and can be reused in every cluster, but also why the other side can't tell pods apart by address.

  4. You apply a NetworkPolicy and nothing changes: every pod can still reach the protected one. Name two possible causes.

    The CNI doesn't enforce network policies (or the feature isn't turned on); or the policy's podSelector doesn't match the pods' actual labels or namespace, so it selects nothing.

  5. Design question: a platform team wants teams to add their own HTTP routes without editing the shared load balancer. Which Kubernetes API fits, and how is responsibility split?

    The Gateway API: the platform team owns the Gateway (load balancer, listeners, certificates) and allows routes from team namespaces; each team owns its HTTPRoute objects attaching to that gateway.

20Serverless and managed services in your network

  1. Why does a VPC-attached Lambda function in a public subnet fail to reach the internet?

    Its interfaces never get public addresses, and an internet gateway only translates for interfaces with public addresses. Its packets have a route but no way to be translated, so they go nowhere.

  2. A function reads from S3 and writes to a private Postgres database. Design its network access with no NAT gateway.

    Attach it to private subnets in two zones; add an S3 gateway endpoint to those subnets' route tables (and interface endpoints for any other AWS services it calls); allow 5432 from the function's security group on the database's (or RDS Proxy's) group. No internet route is needed.

  3. After a database failover, half the app servers keep failing for ten minutes. What's the likely cause?

    Those servers cached the endpoint's old address, through a long DNS cache in the runtime or connection pools holding connections to the old primary. Use endpoint names, keep client DNS caching short, and validate or recycle pooled connections on errors.

  4. Why does serverless code need a connection pooler more than a fleet of long-running servers does?

    Concurrency scales to hundreds of short-lived copies, each opening its own connection, faster than old connections close. Long-running servers keep a small, steady pool each. A pooler like RDS Proxy shares a few database connections among all those copies.

  5. On Google Cloud, you reserve 10.20.0.0/16 for private services access. What's the risk?

    That range is peered into your VPC for managed services, so it can't overlap any network you'll connect later. Larder's production VPC uses 10.20.0.0/16, so connecting the two clouds would be impossible. Reserve it from the address plan like any other block.

21Service mesh and zero-trust networking

  1. In one sentence each: what does a VPN grant, and what does an identity-aware proxy grant?

    A VPN grants the device a place on the network, from which routing and firewalls decide what it can reach. An identity-aware proxy grants a verified person on a checked device access to one application, request by request.

  2. Why keep security groups if every service authenticates every call with mTLS?

    Defence in depth: if a certificate is stolen, a policy is wrong, or a service has a bug that skips checks, network controls still limit what a compromised workload can even connect to. They also reduce noise and attack surface for things that shouldn't talk at all.

  3. A team of six runs eight services on EKS and wants encryption between them. Do they need a service mesh?

    Probably not. TLS between services (certificates from a private CA or cert-manager), network policies and security groups for pods cover encryption and reachability at much lower operational cost. Revisit when service count, teams or per-call authorisation needs grow.

  4. What did the lab's failed connection without a client certificate demonstrate?

    That the server decided whom to talk to by cryptographic identity, not by network position: a client on the same machine, with full network access, was refused because it couldn't prove an identity signed by the trusted CA.

  5. How does SSO with SCIM fix the leaver problem from Larder's review?

    Access to every tool is granted through the identity provider, which HR's system updates automatically. When HR closes a record, SCIM removes the account and groups everywhere, and the identity-aware proxy refuses the next request; there's no separate VPN profile or tool account left behind.

22Observing and troubleshooting networks

  1. About half of requests from a service to a database time out, steadily. The service runs in two zones. What do you check first?

    What differs between the zones: the database's security group or NACL rules (a range covering only one zone's subnet), each zone's route tables, or a per-zone component such as a NAT gateway or endpoint. Flow logs grouped by source subnet will show it quickly.

  2. Flow logs show ACCEPT at the source and nothing at the destination. What does that suggest?

    The packets left the source but never arrived: usually a missing or wrong route (or a gateway dropping them), not a security group or NACL, which would show as REJECT at the destination.

  3. Why might a name-resolution problem not show up in flow logs at all?

    Queries to the VPC's own resolver aren't captured by flow logs. Use Route 53 Resolver query logs to see DNS activity.

  4. When would you use Network Access Analyzer instead of Reachability Analyzer?

    When the question is “which paths exist that shouldn't?” across many resources, such as anything reachable from the internet in the data subnets, rather than “does this one path from A to B work?”.

  5. A busy service drops packets at peak, its CPU is at 40% and nothing is rejected in flow logs. Where do you look?

    At the instance's network allowance metrics (bw_in_allowance_exceeded, pps_allowance_exceeded, conntrack_allowance_exceeded): it may be hitting its bandwidth, packet-rate or tracked-connection limits. Fixes: a larger or network-optimised instance type, more instances, or fewer connections.

23The cost of moving bytes

  1. Which of these are free on AWS: data in from the internet, S3 via a gateway endpoint, traffic between two zones, traffic inside one zone on private addresses?

    Free: data in from the internet, S3 via a gateway endpoint, and traffic within a zone on private addresses. Charged: traffic between zones, in each direction.

  2. A server in zone b sends 1 TB a month to the internet through a NAT gateway in zone a. List the charges.

    Cross-zone transfer (both directions, roughly $20 for 1 TB), NAT processing (about $45–50), and internet egress (about $90), plus the NAT gateway's hourly charge. A NAT gateway in zone b would remove the cross-zone part.

  3. Why might peering two VPCs that already share a transit gateway save money, and why does routing still work?

    Peering has no per-GB processing charge, unlike the TGW. With a summary route to the TGW and the peer's exact range to the peering, longest prefix match sends their traffic over the peering (Chapter 11).

  4. Why is putting everything in one zone a bad way to cut cross-zone costs?

    A zone failure would then take the whole service down. Replication and load balancing across zones are the reason zones exist; cut cross-zone traffic that adds no resilience instead.

  5. Your bill shows NatGateway-Bytes growing fast. How do you find out what's behind it?

    Query flow logs on the NAT gateways' interfaces (or with traffic-path) for the largest byte counts by source and destination, name the flows, and check whether they go to AWS services that endpoints could serve, or to destinations that shouldn't be contacted at all.

24Networks as code and landing zones

  1. Name four things a good VPC module should do without being asked.

    Any four of: take its range from IPAM; create aligned tiered subnets per zone; associate every subnet with an explicit route table and keep the main table local-only; add S3/DynamoDB gateway endpoints; turn on flow logs and query logging; attach to the transit gateway's correct route table; associate the company's private zones; tag for cost and ownership.

  2. Why keep the transit gateway's code and state separate from teams' VPC code?

    So a team's change can never plan to modify the shared hub, plans stay fast and small, and the central network changes only through its own careful review.

  3. Which rule would you enforce with an SCP, and which with a CI check: “no internet gateways in workload accounts” and “every security group rule has a description”?

    The internet gateway rule is absolute and security-critical: an SCP. Descriptions are good hygiene with occasional exceptions and no security impact by themselves: a CI check.

  4. Two product teams exchange a lot of traffic and share releases. Shared VPC or a VPC each?

    A shared VPC fits: their traffic stays inside one VPC (free within a zone, no TGW charges), and they gain little from separate network autonomy. Isolation between them still comes from security groups.

  5. An incident is caused by a subnet left on the main route table. What's the full fix?

    Fix the subnet's association now; then make the module always associate subnets explicitly and keep the main table local-only, and add a check (CI or Config rule) that flags any subnet on a main table, so it can't happen in any VPC again.

25Capstone: design Larder's network end to end

  1. Why are store VPN connections to Paris created during failover rather than kept running?

    Each VPN connection is charged by the hour; one per store would exceed the pilot light's budget. With pre-generated configurations and router settings in place, creating them takes minutes, well within the four-hour RTO.

  2. Why isn't the failover to Paris automatic, with health-checked DNS?

    A pilot light can't serve traffic until it's scaled up and the database is promoted, and an unnecessary failover is costly and risky. The ADR sets a trigger (an outage longer than an hour), and people decide; automatic DNS failover suits warm standbys that are already serving.

  3. Pick three items from the review checklist that would have prevented incidents told in this book, and name the incidents.

    For example: explicit subnet associations (the reporting subnet on the main table, Ch. 8); routes in both directions (Rotterdam's missing return route, Ch. 4); rules between roles (the Dispatch outage, Ch. 9); keep-alives longer than idle timeouts (the 502s, Ch. 16); an inventory of egress destinations (the poisoned package, Ch. 18).

  4. In the game day where one zone is blocked, what would a failure tell you?

    That something is still single-zone: a NAT gateway or endpoint used by all zones, a subnet group or function config with one zone, uneven targets without cross-zone balancing, or a client pinned to one replica. Fix the design, then repeat the drill.

  5. Which of Larder's decisions would you revisit first if it hit the ADR's “60,000 orders a day” trigger, and why?

    The pilot light itself: at that scale an outage's cost grows, so a warm standby or active-active second region may now be cheaper than the expected loss. Close behind: Direct Connect thresholds if a central warehouse appears, and service-to-service identity if service count grows past the mesh threshold.
