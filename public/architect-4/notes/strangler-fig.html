Strangler Fig Migration

TL;DR

Replacing a system in one big weekend bets everything on one night with no way back. A strangler fig migration replaces it piece by piece while it keeps running: put a router in front that sends each piece (a store, a feature, a customer group) to the old or the new system; move one piece at a time, with a shadow period and a way back; and when nothing is left on the old system, switch it off.

  • Lives in: a router in the owning module, a migration plan with dates

1The situation Larder, 29 March 2027

The first plan for the warehouse move (ADR 0016) is a big bang: all five stores switch from StockPilot to WMS B on one Saturday night in July. It looks efficient. But if anything goes wrong, every store opens on Sunday without trustworthy stock, and going back means losing a day of movements. Joost says what everyone is thinking: “not on my Sundays”.

  • Big-bang migrations concentrate all the risk in one moment.
  • Problems show up everywhere at once, at the worst time.
  • There's no small step to learn from, and no easy way back.

2Real-life analogy the bridge, lane by lane

Road engineers replace a busy bridge lane by lane. Traffic keeps flowing on the old lanes while one new lane is built and opened; then the next. Each step is small, the bridge never closes, and if a new lane has a problem, cars go back to an old one for a while. One day the last old lane is closed for good.

3How it solves it router, one piece at a time, a way back

Because the Stock module already held the only adapter (ADR 0005, 0018), adding a router was small: a setting per store chooses StockPilot or WMS B. Each move had a week of shadow mode (both systems updated, stock compared), then the switch, then two weeks with StockPilot read-only as a way back. Zuid went first in April (smallest), The Hague opened directly on WMS B in June, Utrecht moved last in July. StockPilot was switched off on 15 September.

  1. Find the seam

    Where calls to the old system pass through one place (an adapter).

  2. Put a router there

    Per store, feature or customer group: old or new.

  3. Pick the first piece

    Small and low-risk, but real.

  4. Shadow, compare, switch

    Run both, compare results, then switch the piece.

  5. Keep a way back

    The old system read-only for a set period.

  6. Repeat, then switch off

    When nothing routes to the old system, turn it off and delete the router branch.

Vocabulary for the exam

Strangler fig
Replacing a system gradually until the old one can be removed.
Router
The switch deciding old or new per piece.
Shadow mode
Running the new system alongside, comparing, without relying on it.
Seam
A place where you can redirect calls.
Way back
A tested route to return to the old system.
Big bang
Switching everything at once.

4Gains vs losses nothing is free

What we gain

  • Small risk per step: one store at a time.
  • Learning early: Zuid found the units problem.
  • A way back after every move.
  • The business keeps running, every Sunday.
  • Progress is visible, store by store.

What we lose

  • Longer overall: months instead of a weekend.
  • Two systems at once, with two bills for a while.
  • Router and shadow code to build and delete.
  • Easy to stall with the last pieces.

6Common pitfalls the usual ways this goes wrong

  • No seam

    Calls to the old system everywhere. Fix → build the single adapter first (ACL).

  • No way back

    Switch and hope. Fix → keep the old system read-only for a set time.

  • The last 10 % stalls

    One store left on StockPilot for a year. Fix → a date for switching off, in the contract too.

  • Router left behind

    Dead branches for years. Fix → delete the router branch when done.

7When to use it (and when not)

Use it when…

  • Replacing a vendor, platform or legacy system.
  • Migrations where downtime is unacceptable.
  • When the work can be split by store, feature or customer.
  • Extracting services from a monolith.

Skip it when…

  • Tiny systems that can be swapped in an hour with a rollback.
  • When the old and new can't run side by side at all.

8Self-check quiz

What does the router do?

Sends each piece (here, each store) to the old or the new system.

What's shadow mode for?

Running both systems and comparing results before relying on the new one.

What's the way back?

The old system kept read-only for a set period after each move.

When is the migration done?

When nothing routes to the old system and it's switched off.

try it

For a system you'd like to replace, find the seam: the one place calls pass through. If there isn't one, that's the first job. Then list the pieces you could move one at a time, and pick the smallest real one to go first.

remember!!

Replace the bridge lane by lane. Keep a way back.
