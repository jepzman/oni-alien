Data Classification & Residency

TL;DR

Data classification gives every kind of data a label by sensitivity (for example public, internal, confidential, restricted), and each label carries rules: where it may be stored (residency), how it's protected, who can see it, how long it's kept, whether it may be used in testing. Then you find every copy (databases, exports, analytics, test environments) and make the rules true. The label does the arguing, so each new design doesn't have to.

1The situation Larder, 25 October 2027

A week after Antwerp opened, Lena asks: where are Belgian customers' data? Ana's first answer is the database in Frankfurt. The real answer is fourteen places, including the product analytics tool storing events in the United States, a spreadsheet export on a shared drive, and a test environment holding a copy of real customers. Nobody had listed the copies.

  • Data spreads into tools, exports and test copies.
  • Without labels, every design argues protection from scratch.
  • Residency rules apply to every copy, not just the main database.

2Real-life analogy the doctor's practice

A doctor's practice keeps appointment times on the noticeboard, staff rotas in the office, patient notes in a locked cabinet and prescription pads in the safe. Nobody debates each sheet of paper: its label decides where it may be kept, who may see it and when it's shredded.

3How it solves it four labels, rules per label, every copy found

Ana and Lena agreed four classes with rules: public anywhere; internal in the EU or vetted vendors; confidential (customer names, addresses, orders) EU only, encrypted, access by role, masked in test, deleted after retention; restricted (payment tokens, age-check results, staff badges) EU only, named systems, every access logged. The inventory found 14 stores of customer data: analytics moved to its EU instance by 30 November, test data masked, exports to shared drives blocked. Every table and topic now carries its class.

  1. Agree three to five classes

    With legal; plain names and examples.

  2. Write rules per class

    Location, encryption, access, retention, test use.

  3. Find every copy

    Databases, topics, tools, exports, backups, test environments.

  4. Tag data with its class

    In the catalogue, on tables, topics and fields.

  5. Fix the gaps

    Move, mask, delete or block, with dates.

  6. Check new designs

    The class decides; a CI check for new tables.

Vocabulary for the exam

Data classification
Labelling data by how sensitive it is.
Data residency
Where (which country or region) data is stored.
Personal data
Information about an identifiable person (GDPR).
Data masking
Replacing real values with realistic fakes for testing.
Retention period
How long data is kept before deletion.
Data catalogue
A list of datasets with owners, classes and locations.

4Gains vs losses nothing is free

What we gain

  • Lena's question answered, for every copy.
  • Rules decided once, applied everywhere.
  • Residency handled before regulators ask.
  • Safer test data.
  • Faster designs: the class decides.

What we lose

  • The inventory takes weeks.
  • Tags drift without checks.
  • Some tools must be replaced or reconfigured.
  • Masked test data is harder to build.

6Common pitfalls the usual ways this goes wrong

  • Too many classes

    Nine levels nobody remembers. Fix → three to five, with examples.

  • Main database only

    Copies in tools and tests ignored. Fix → inventory every copy.

  • Labels without rules

    “Confidential” changes nothing. Fix → rules per class.

  • One-off exercise

    New tables untagged. Fix → a CI check for new data.

7When to use it (and when not)

Use it when…

  • Entering a new country or market.
  • Before a privacy audit or a client's questionnaire.
  • Adding analytics, AI or reporting tools.
  • When test environments use production data.

Skip it when…

  • Never entirely; even a small product holds personal data.

8Self-check quiz

What does a data class carry?

Rules: where data may live, protection, access, retention and test use.

What did Larder's inventory find?

Fourteen stores of customer data, including US analytics and a real test copy.

What is data residency?

Which country or region the data is stored in.

How do new tables get a class?

A CI check requires every new table and topic to declare one.

try it

Pick one kind of personal data in your product (say, addresses). Find every place it's stored, including tools, exports, backups and test environments. Give it a class, write its rules, and list the copies that break them.
