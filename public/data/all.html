Data & Database Patterns

Modelling, fast reads, safe changes and growing tables: the patterns that keep a database correct, quick and calm to run.

Modelling shape the tables before the data piles up

  1. 01NormalizationStore each fact once so it can't disagree with itself; copy it only on purpose.p. 01
  2. 02Surrogate KeysGive every row a meaningless, stable id instead of keying on real-world values.p. 02
  3. 03Soft DeleteMark rows as deleted instead of removing them, so they can be restored or audited.p. 03
  4. 04History Tables (Audit Trail)Keep every past version of a row, so you can answer “what was it on that day?”p. 04

Reading fast get answers back without scanning everything

  1. 05IndexingKeep a sorted lookup next to the table so queries jump to rows instead of scanning.p. 05
  2. 06Batch Loading (Fixing N+1)Fetch related rows in one query instead of one query per row.p. 06
  3. 07Keyset PaginationPage with “after this key”, not OFFSET, so page 1,000 is as fast as page 1.p. 07
  4. 08Materialized ViewsSave the result of an expensive query as a table and refresh it on a schedule.p. 08

Changing safely write, migrate and share changes without losing data

  1. 09Optimistic LockingDetect when someone else changed a row first, instead of silently overwriting it.p. 09
  2. 10Expand & Contract MigrationsChange the schema in small backward-compatible steps, with no downtime.p. 10
  3. 11Change Data CaptureStream every committed change from the database log to other systems.p. 11

Growing keep it healthy at 100× the rows and tenants

  1. 12Table PartitioningSplit one huge table into smaller pieces by date or key, inside one database.p. 12
  2. 13MultitenancyServe many customers from one database while keeping each one's data apart.p. 13
  3. 14Connection PoolingReuse a small set of open connections instead of opening one per request.p. 14
  4. 15Star SchemaShape analytics data as facts surrounded by dimensions, for fast reports.p. 15
