Ask the question first; the type follows. One grain per table, always.

The grain sentence

  • “One row per order line”
  • “One row per product · shop · month”
  • “One row per order, updated”
  • Measures must be true at that grain
  • ! Order-level shipping on every line → summed 3×
  • Store the finest grain you can afford

Can I add it up?

additive
sum across everything: qty, amount
semi-additive
not across time: stock on hand, balance → last or avg
non-additive
ratios, %: store the parts, divide at the end
distinct count
doesn't roll up: count from facts or merge HLL sketches

Point-in-time lookup

Three pasts

questioncalledhow
Kitchen revenue in Marchas it wastype 2 join on the fact's key

History traps

  • ! Facts joined on the natural key → every version matches, totals double
  • ! BETWEEN on validity → boundary in two versions
  • ! Versions dated by load day → backdated moves land late
  • ! Missing version → fact dropped; use an inferred member
  • ! Type 2 on last_login → millions of versions a day
  • ! Nightly snapshot → changes between runs are lost

Test every load: one current row per key; no overlapping ranges (a.from < b.to AND b.from < a.to).

Trust & servingtests, reconciliation, drill across, aggregates, one metric definition

4/4card

← swipe the diagram →

Reconcile with the sourcenightly

Old days must match exactly. A difference names the day to replay. The best single test you can run.

Data tests

  • keys unique and not null
  • foreign keys resolve (or point at -1)
  • values in range: 0 < price < 2,000
  • count and sum within ±30 % of the same weekday
  • quarantined rows < 1 % of the batch
  • freshness: newest event < 45 min old

Row failures → quarantine table with a reason. Batch failures → don't publish.

Drill across

! Never join two facts row to row: aggregate each, then join.

Aggregates

Store sums and counts; averages = sum / count. Distinct counts: merge sketches.

One metric, defined oncemetrics layer

Only your rows

Tenant from a signed token, never the URL. Tenant in every cache key.

Before you publish a number

  • The grain of every table it reads is written down
  • Its definition lives in one place, with an owner
  • It says as it was or as it is
  • The page shows data as of
  • Filed numbers are stored when they're sent
