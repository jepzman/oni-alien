Data Pipelines & Analytics

My notes on getting data out of the app and into reports people trust: how to extract and load it so a rerun never double-counts, how to model a warehouse past one star, how to keep it trustworthy, and how to serve one number everywhere. 18 patterns in four collections, with the same eight sections as the other volumes, rated on nine pipeline qualities like freshness, correctness and replayability. Every note follows the same homeware shop: a web store and 30 shops, orders, order lines, products and customers. SQL is generic warehouse SQL; tools named are examples.

Getting data in extract and load without losing or doubling a row

  1. 01ETL vs ELT rethoughtTransform before loading, or load raw data and transform it inside the warehouse.p. 01
  2. 02Incremental ExtractCopy only what changed since last time, using a high-water mark, without missing late rows.p. 02
  3. 03Idempotent LoadsLoad so that running the same batch twice gives the same table as running it once.p. 03
  4. 04Layered Zones (Raw, Staging, Marts)Keep raw data untouched, clean it in staging, and shape it for reports in marts.p. 04
  5. 05Late-Arriving DataPut each event in the period it happened, even when it reaches you days later.p. 05

Modelling the warehouse shapes that answer questions and keep history

  1. 06Slowly Changing Dimensions still coreDecide per column whether a change overwrites the past or adds a new version.p. 06
  2. 07Fact Table Types still coreTransactions, periodic snapshots, accumulating snapshots and factless facts: pick by question.p. 07
  3. 08Conformed Dimensions & the Bus Matrix matters more nowShare one product, one customer and one calendar across every fact table.p. 08
  4. 09Data Vault rethoughtHubs, links and satellites: an insert-only layer that integrates many sources and keeps all history.p. 09
  5. 10One Big Table vs Star rethoughtFlatten everything into one wide table, or keep facts and dimensions apart: choose by engine and team.p. 10

Keeping it trustworthy stop bad data before anyone reads it

  1. 11Write–Audit–PublishBuild into a hidden table, test it, and swap it in only when the tests pass.p. 11
  2. 12Data ContractsAgree a versioned schema and rules with the team that produces the data.p. 12
  3. 13Quality Checks & QuarantineTest rows and whole batches on every load; set bad rows aside instead of loading them.p. 13
  4. 14DAG Orchestration & LineageRun steps when their inputs are ready, not at a time on the clock, and know what feeds what.p. 14

Serving reports one number, fast, for everyone allowed to see it

  1. 15Metrics LayerDefine each business number once, in code, and let every dashboard use that definition.p. 15
  2. 16Aggregates & RollupsPre-compute summaries at coarser grain so dashboards stay fast on billions of rows.p. 16
  3. 17Lambda vs Kappa rethoughtFresh numbers from a batch plus a speed layer, or from one stream you can replay.p. 17
  4. 18Multi-tenant & Embedded ReportingShow each customer or shop only their own numbers, without slowing the app down.p. 18

★The nine pipeline ratings what finance would ask, and the on-call engineer

Every note scores the pattern from 1 (poor) to 5 (great) on the same nine things, comparing an app without the pattern to the same app with it.

Simplicity
A new teammate can trace a number from the report back to the source.
Freshness
How old the data in the report is when someone reads it.
Correctness
No missing, doubled or misfiled rows, even after failures.
Replayability
Any step can be run again, for any period, and give the same result.
Scalability
Keeps working when sources, rows and users grow by 10× or 100×.
Low cost
Compute, storage and the people who keep it going. High = cheap.
Query flexibility
Analysts can ask new questions without a new pipeline.
Observability
Failures, delays and bad data are seen before the report is read.
Evolvability
New sources, columns and definitions without rebuilding everything.

first law

A pipeline is correct only if you can run any part of it again, for any day, and get the same answer. Everything else is plumbing.
