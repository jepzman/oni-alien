Cloud & DevOps Patterns

Shipping safely, infrastructure as code, running and observing, and resilience and cost: the patterns behind calm deploys and boring on-call.

Shipping safely get changes to users in small, reversible steps

  1. 01Blue–Green DeploymentRun the new version next to the old one and switch traffic in one step.p. 01
  2. 02Canary ReleasesSend a small share of traffic to the new version and widen it only if metrics stay healthy.p. 02
  3. 03Feature FlagsShip code switched off, then turn features on for chosen users without a deploy.p. 03
  4. 04Build Once, Deploy ManyBuild one immutable artefact and promote the exact same thing through every environment.p. 04

Infrastructure as code describe every server, network and environment in files

  1. 05Infrastructure as CodeDescribe cloud resources in reviewed, versioned files instead of clicking in consoles.p. 05
  2. 06GitOpsGit holds the desired state; an agent keeps the cluster matching it.p. 06
  3. 07Immutable InfrastructureNever patch servers in place; replace them with fresh ones built from an image.p. 07
  4. 08Preview EnvironmentsSpin up a short-lived copy of the app for every pull request.p. 08

Running & observing keep services healthy and see what they're doing

  1. 09Health Checks & ProbesLet the platform ask each instance “are you alive? are you ready?” and act on it.p. 09
  2. 10AutoscalingAdd and remove capacity automatically as load rises and falls.p. 10
  3. 11Logs, Metrics & TracesEmit structured signals so you can answer new questions about production.p. 11
  4. 12SLOs & Error BudgetsAgree how reliable is reliable enough, and spend the rest on shipping.p. 12

Resilience & cost recover from the worst day, learn from it, and pay less

  1. 13Backups & Disaster RecoveryKeep tested backups and a rehearsed plan to restore service elsewhere.p. 13
  2. 14Incident Response & PostmortemsHandle incidents with clear roles, then learn from them without blame.p. 14
  3. 15Cost Visibility (FinOps)Tag, measure and own cloud spend, so cost is a design input, not a surprise.p. 15
