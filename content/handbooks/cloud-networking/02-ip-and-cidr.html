IP addresses and CIDR without fear

Every cloud network starts with a line like 10.20.0.0/16, and most network mistakes start there too: a range that's too small, two ranges that overlap, a subnet that doesn't start where you thought. This chapter makes address ranges something you can read, split and check in your head, with just enough binary to see why the rules are what they are.

By the end you can

  • Read CIDR notation and say how many addresses a range holds.
  • Tell whether an address belongs to a range, and find a range's first and last address.
  • Split a range into subnets that don't overlap.
  • Recognise the special ranges: private, link-local, documentation, and IPv6.

  • Python 3 for the lab (it's installed on most Macs and Linux machines).

At Larder

Larder's first VPC was created by Jasper, the co-founder, in an afternoon: 172.17.0.0/16, because it was the example in a blog post. It worked for two years. Then Eli tried to run the reporting jobs in Docker containers on one of the servers, and every call from a container to the database timed out.

Nothing was wrong with the database, the security groups or the routes. The problem was in the address range itself, and by section 2.7 you'll be able to spot it at a glance.

2.1The big picture

An IPv4 address is a 32-bit number. We write it as four decimal numbers between 0 and 255, separated by dots, because that's easier on people than 32 ones and zeros: 10.20.17.8. Each of the four numbers is called an octet, because it stands for eight bits.

Networks rarely talk about single addresses. They talk about ranges: “everything from 10.20.0.0 to 10.20.255.255”. Route tables match ranges, firewalls allow ranges, and every VPC and subnet is a range. The modern way to write a range is CIDR notation (Classless Inter-Domain Routing): an address, a slash, and a number.

Key idea

10.20.0.0/16 means: every address whose first 16 bits are the same as the first 16 bits of 10.20.0.0. The number after the slash is how many bits are fixed.

The fixed bits are the network part (also called the prefix), and the remaining bits are the host part, free to vary. A /16 fixes 16 bits and leaves 16 free, so it holds 216 = 65,536 addresses. That one sentence is most of what this chapter is about. The rest is practice.

2.2Binary in five minutes

You only need binary for one thing: seeing where the network part ends when the slash isn't a multiple of 8. Each octet is eight bits, and each bit is worth twice the one to its right:

2.3How big is a range?

A range with prefix /n has 32 − n host bits, so it holds 232−n addresses. Each step of the prefix halves or doubles the size: a /23 is twice a /24, a /25 is half of one.

Remember that the provider keeps some addresses in every subnet: five on AWS and Azure, four on Google Cloud (Chapter 8). A /24 gives you 251 usable addresses on AWS, not 256.

Watch out

The slash counts fixed bits, so a bigger number means a smaller range. A /28 is tiny and a /16 is big. When someone says “give me a bigger subnet”, they want a smaller number after the slash.

2.4Is this address in that range?

This is the question behind every route lookup and every firewall rule, and you'll ask it constantly while debugging. For prefixes that are multiples of 8, just compare whole octets: 10.20.99.1 is in 10.20.0.0/16 because the first two octets match.

For any other prefix, use the block size method. It works entirely in decimal:

  1. Find the interesting octet: the one where the prefix ends. For /20, the first 16 bits cover two octets, and the remaining 4 fixed bits fall in the third octet.
  2. Find the block size: 2 to the power of the host bits in that octet. The third octet has 8 − 4 = 4 host bits, so blocks are 24 = 16 wide.
  3. Round down the address's interesting octet to a multiple of the block size. For 10.20.17.8: 17 rounds down to 16.
  4. Read off the range. The network is 10.20.16.0/20, running from 10.20.16.0 to 10.20.31.255 (16 + 16 − 1 = 31).

2.5Splitting a range into subnets

Designing a network means cutting one big range into smaller ones that don't overlap. Every extra bit you add to the prefix splits a range in two: a /16 becomes two /17s, four /18s, sixteen /20s, or 256 /24s.

There's one rule that makes this safe, and it's the rule people break most often:

Key idea

A block always starts on a multiple of its own size. A /20 (16 wide in the third octet) can start at .0, .16, .32, .48… and nowhere else.

So 10.20.8.0/20 isn't a valid network: 8 isn't a multiple of 16. Its host bits aren't all zero. Some tools quietly change it to 10.20.0.0/20, others reject it, and AWS refuses to create the subnet. Either way, it's not what you meant.

Mixing sizes

Real plans mix sizes, as Figure 2.2 does. The easy way to stay safe: allocate the biggest blocks first, each at the next aligned position, and cut the small ones out of a block you've set aside for them. If you place small subnets first, you leave odd-sized gaps that no large block can fit into.

2.6Public and private addresses

Public IPv4 addresses are unique across the whole internet and they're scarce: all 4.3 billion are handed out. So three ranges were set aside (in RFC 1918) for private addresses, which anyone may use inside their own network and which are never routed on the internet:

Table 2.4 · Special IPv4 ranges
RangeWhat it's forWhere you'll meet it
10.0.0.0/8Private (RFC 1918)Most company and cloud networks. Plenty of room.
172.16.0.0/12Private (RFC 1918): 172.16.0.0–172.31.255.255AWS default VPCs (172.31.0.0/16), Docker (172.17.0.0/16)
192.168.0.0/16Private (RFC 1918)Home routers. Avoid in the cloud: it clashes with people's VPN clients at home.
100.64.0.0/10Shared address space for carrier NATSome providers' internal services; sometimes used for Kubernetes pods (Ch. 19)
169.254.0.0/16Link-local169.254.169.254: the instance metadata service on AWS, Azure and Google Cloud
127.0.0.0/8Loopback: this machine127.0.0.1, “localhost”
192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24Documentation onlyExamples in books like this one. Never routed.

A private address can't be reached from the internet directly. When a machine with one needs to reach the internet, something along the way swaps its private source address for a public one: your home router does it for your laptop, and a NAT gateway does it for private servers in the cloud (Chapter 8).

Public IPs cost moneyBecause they're scarce, AWS charges for every public IPv4 address, in use or not, at about $3.60 a month each. Another reason to keep servers private and share a few public addresses through NAT and load balancers.

2.7Overlap: the mistake that lasts for years

Two ranges overlap when they share any addresses. Inside one network that breaks routing, because the same address has two possible meanings. Across networks it means they can never be connected with plain routing: peering, VPNs and transit gateways all refuse or misbehave when ranges overlap (Chapter 11).

Overlap is easy to check with what you've learned: two aligned blocks either don't overlap at all, or one sits entirely inside the other. Find the larger block, and check whether the smaller block's first address falls inside it.

At Larder: solved

Jasper's VPC was 172.17.0.0/16. Docker's default bridge network, which it creates on every host for its containers, is also 172.17.0.0/16. Inside a container, the database at 172.17.3.20 looked like a neighbour on the local Docker bridge, so packets went to the bridge and never left the server. The route table on the host was doing exactly what it was told.

The quick fix was to move Docker's bridge to another range in /etc/docker/daemon.json. The real fix took longer: Larder's new VPC, the one you met in Chapter 8, uses 10.20.0.0/16, from a company-wide plan in 10.0.0.0/8 that leaves 172.16.0.0/12 to tools that like to claim it (Chapter 10).

2.8Enough IPv6 to not be scared of it

IPv6 was designed to end the address shortage. An IPv6 address has 128 bits, written as eight groups of four hexadecimal digits separated by colons:

2001:0db8:0000:0001:0000:0000:0000:0005

Two shortcuts make that bearable. Leading zeros in a group can be dropped, and one run of all-zero groups can be replaced by ::. So the address above is 2001:db8:0:1::5.

CIDR works exactly the same way, just with more bits. The sizes are so large that the habits are different:

  • A subnet is always a /64: 64 bits of network, 64 bits of host. That's 18 quintillion addresses per subnet, so you never size subnets by host count again.
  • On AWS, a VPC gets a /56 from Amazon's pool (or from addresses you bring), which holds 256 /64 subnets. Azure and Google Cloud also use /64 subnets.
  • Cloud IPv6 addresses are usually globally unique and public. There's no NAT. Whether a server can be reached from the internet is decided by routing and firewalls alone. To let IPv6 servers go out but not be reached, AWS has an egress-only internet gateway.
  • Documentation examples use 2001:db8::/32, like the address above.

Most cloud networks today are dual stack: every subnet has an IPv4 range and an IPv6 range, and services listen on both. This book uses IPv4 in most examples because that's what you'll debug most often, and notes where IPv6 behaves differently. Chapter 10 covers when to adopt it.

2.9Let the computer check your maths

Do the arithmetic by hand until it's familiar, then let tools do it, especially in anything you'll apply to a real network. Three are worth knowing.

Python's ipaddress module

python3no install needed

import ipaddress as ip

vpc = ip.ip_network("10.20.0.0/16")
vpc.num_addresses                                 # 65536
ip.ip_address("10.20.17.8") in ip.ip_network("10.20.16.0/20")   # True
list(vpc.subnets(new_prefix=18))                # four /18s
ip.ip_network("10.20.16.0/20").overlaps(ip.ip_network("10.20.0.0/16"))  # True
ip.ip_network("10.20.8.0/20")                    # ValueError: has host bits set

Terraform's cidrsubnet

In infrastructure code you rarely type subnet ranges. You derive them from the VPC's range, so they can't drift out of line. cidrsubnet(range, newbits, netnum) adds newbits to the prefix and returns block number netnum:

cidrsubnet("10.20.0.0/16", 8, 2)   # "10.20.2.0/24"   (/16 + 8 bits = /24, block 2)
cidrsubnet("10.20.0.0/16", 4, 3)   # "10.20.48.0/20"  (/16 + 4 bits = /20, block 3)

That's how the lab in Chapter 8 built its subnets.

Your cloud provider's IPAM

Once there are many teams and VPCs, a spreadsheet stops being enough. AWS VPC IP Address Manager, Azure Virtual Network Manager's IP address management and similar tools hand out non-overlapping ranges from a central pool. They're the subject of Chapter 10.

2.10Lab: practise until it's boring

Lab 2 · Subnet a VPC by hand, then check it

You'll design a subnet plan on paper and check it with Python. You need Python 3 and, for the last step, Terraform or OpenTofu. Cost: nothing; nothing is created in the cloud.

  1. Warm up by hand. Without tools, write down the first and last address and the size of: 10.0.0.0/22, 10.1.4.0/23, 192.168.10.128/25, 10.30.40.0/21. Then check each with ip.ip_network("…"), its [0], [-1] and num_addresses.
  2. Spot the invalid ones. Which of these aren't valid networks: 10.0.3.0/22, 10.0.4.0/22, 10.0.6.0/23, 10.0.7.0/23? Work it out, then let Python tell you.
  3. Design a plan. You have 10.40.0.0/16 and three zones. You need a public /24, an app /20 and a data /24 per zone, with half the range kept free. Write the nine subnets down, biggest first.
  4. Check it. Put your nine ranges in a Python list and run this to find overlaps and confirm they all fit in the VPC: 
    plan = [ip.ip_network(c) for c in ["10.40.0.0/24", ...]]
vpc = ip.ip_network("10.40.0.0/16")
for i, a in enumerate(plan):
    assert a.subnet_of(vpc), a
    for b in plan[i + 1:]:
        assert not a.overlaps(b), (a, b)
print("plan OK")
  5. Express it in Terraform. Run terraform console in an empty folder and reproduce your nine ranges with cidrsubnet() calls. If one doesn't match, your plan or your netnum is off by a block.

Stretch goal. Find the ranges your own computer uses: your home network, any VPN, Docker (docker network inspect bridge). Would any of them clash with a VPC in 172.16.0.0/12?

✓Chapter summary

  • An IPv4 address is 32 bits, written as four octets. CIDR /n fixes the first n bits; the range holds 232−n addresses.
  • A bigger number after the slash means a smaller range.
  • To place an address, use the block size in the octet where the prefix ends, and round down.
  • Blocks must start on a multiple of their size. Aligned blocks either nest or don't overlap at all.
  • Use RFC 1918 private ranges, plan inside 10.0.0.0/8, and avoid ranges your tools already claim.
  • IPv6: 128 bits, /64 subnets, usually public, no NAT; reachability is down to routes and firewalls.

Key terms

Octet
One of the four 8-bit numbers in an IPv4 address.
CIDR notation
A range written as address/prefix length, like 10.20.0.0/16.
Prefix / network part
The fixed leading bits shared by every address in a range.
Host part
The remaining bits, which vary inside the range.
Subnet mask
The prefix written as an address of ones then zeros, like 255.255.255.0.
Block size
How wide a range is in the octet where its prefix ends.
Private address
An address from the RFC 1918 ranges, never routed on the internet.
Overlap
Two ranges sharing any addresses; blocks routing between them.
Dual stack
Running IPv4 and IPv6 side by side on the same network.

Check your understanding

  1. How many addresses are in a /21, and how many could you use for servers on AWS? recall

    Show answer

    232−21 = 211 = 2,048 addresses, of which 2,043 are usable on AWS (5 are reserved).

  2. Which /20 network contains 10.20.200.9? Give its first and last address. apply

    Show answer

    Blocks of 16 in the third octet: 200 rounds down to 192. So 10.20.192.0/20, from 10.20.192.0 to 10.20.207.255.

  3. Do 10.8.0.0/14 and 10.10.0.0/16 overlap? apply

    Show answer

    Yes. A /14 is a block of 4 in the second octet, so 10.8.0.0/14 covers 10.8 to 10.11, which includes all of 10.10.0.0/16.

  4. A teammate proposes subnets 10.20.0.0/24, 10.20.1.0/24 and 10.20.2.0/20. What's wrong, and how would you fix it? explain

    Show answer

    10.20.2.0/20 isn't aligned: a /20 must start at a multiple of 16 in the third octet, so it's really 10.20.0.0/20, which overlaps the two /24s. Place the /20 at 10.20.16.0/20, or allocate the /20 first and put the /24s elsewhere.

  5. Why can't you just create a /16 for every team and stop worrying about addresses? design

    Show answer

    You can, if they come from a plan that keeps them from overlapping each other and your offices. 10.0.0.0/8 holds 256 /16s, which is plenty for most companies, but only if they're handed out centrally. The danger isn't size, it's two teams picking the same range and later needing to connect.

  6. An IPv6-only server in a public subnet has no NAT in front of it. How do you stop the internet from reaching it while still letting it download updates? compare

    Show answer

    With routing and firewalls, not NAT. On AWS, route its IPv6 default route through an egress-only internet gateway, which allows outbound connections and their replies but nothing inbound, and keep its security group closed to inbound traffic.
